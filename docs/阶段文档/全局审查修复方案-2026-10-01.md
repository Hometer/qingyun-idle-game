# 全局审查修复方案（2026-10-01）

> 依据 `docs/阶段文档/全局审查-2026-10-01/全局审查报告.md`。按报告推荐顺序分三批修复，每批保留现有测试并补回归；修复后走真实动作→导出→导入→刷新/重启复验，资源只结算一次。修复前阶段 3 保持待验收，不宣称通过。

## 第一批：存档、炼器入口、反重复领奖、费用保护（P1-01/02/03/05/06）

### P1-01 正常操作产生的存档无法导回（3 条独立路径）

1. **收益丹库存校验漏 `yangYuanDan_*`/`juLingDan_*`**（`engine.ts:validateEquipmentAndInventory`）
   - 校验循环里补 `k.startsWith("yangYuanDan_") || k.startsWith("juLingDan_")` 放行；零数量键容忍（`x === 0` 不判非法）。
2. **风共鸣闭关合法耗时被拒**（`engine.ts:startLongTask` / `validateLongTask`）
   - `LongTask` 快照增加 `effectiveMinutes`（风共鸣缩短后的实际耗时）；`startLongTask` 写入；`validateLongTask` 按 `effectiveMinutes` 核算 `endAt = startAt + effectiveMinutes*60*1000`，不再按原 `durationMinutes` 固定核算。
3. **封存词条重铸溢出**（`engine.ts:reforgeEquipment`）
   - 重铸生成时先放入已锁定词条（占用 1 个名额），再从剩余词条池抽足到上限，杜绝抽中集合不含锁定 ID 时超上限。

### P1-02 坏档崩溃 + 委托重领奖

1. `marrowHistory`：`validateMilestonesAndFirsts` 增补 `marrowHistory` 逐项结构校验（每项为对象、字段类型正确、时间非负），`[null]` 拒绝导入。
2. 命盘/共鸣关系：新增 `validateSpiritRoots` —— `spiritRoots` 为非空无重复的合法五行/变异集合；`resonance` 若非空必须属于 `spiritRoots`。
3. 委托关系：`validateCommission` 增补——`active` 与 `history` 不得同时指向同一实例身份；`status="claimed"` 必须带 `rewardChoice` 与 `claimedAt`；`rewardChoice`/`claimedAt` 只在 `claimed` 出现。跨日同类型候选 ID 用「类型+目标+日期」区分，防重领奖按实例身份，不简单禁止所有同类型历史。

### P1-03 炼器台入口判错（`beibao/page.tsx`）

- 总入口条件 `state.forge < CONFIG.forge.levels.length` 改为 `state.forge < 1`（未建造才隐藏）；每个配方分别显示所需炼器台等级、境界与材料差额。

### P1-05 日期回拨重复领奖

- `ensureDaily`/`ensureSecretRealm`/`ensureCommission` 统一改为**日期高水位不回拨**：仅当 `today > 已记录日期` 才重置/重新生成；`today < 已记录日期`（回拨）保持不变，不刷新额度、不重生成候选。

### P1-06 模型失败不记费用（`backend/app/services/llm.py`）

- `record_usage` 上移到**收到 `usage` 即记账**（解析/审核之前），失败与重试也计入；每次重试前预留费用；`budget._load` 遇损坏账本时显式失败（`RuntimeError`）或安全降级（记 0 并告警），不静默清空已有额度；`OpenAI` 初始化指定 `max_retries=0`，与业务两层重试对齐。

## 第二批：成长规则、装备实例、迁移版本（P1-04 + P2-01/02/07）

### P1-04 境界门槛与费用漏实现

统一在 `config.ts` 给建筑/功法/藏经阁/炼器台/配方补 `gate` 字段，引擎在「展示、预览、结算、导入校验」共用同一套规则（不可各处写死）：

1. **四基础建筑**（修炼室/聚灵阵/灵田 Lv4~8、炼丹炉 Lv4~6）逐级 `gate`：元婴一层/大乘一层/金仙一层/混元大罗一层/大道圣人一层（炼丹炉为 元婴/真仙/混元大罗一层）；`upgradeBuilding` 校验境界不足不扣费。
2. **炼丹炉 Lv4/5/6 升级费用**补残页 100/600/2500（`cost` 改为 `{spiritStone, page}`，保留现行护劫丹成本逻辑）。
3. **藏经阁 Lv3~7、炼器台 Lv2~6** 逐级 `gate`（元婴/大乘/金仙/混元大罗/大道圣人一层），`buildLibrary`/`buildForge` 按当前等级查 gate。
4. **四基础功法 Lv4~12** 逐级开放境界（金丹/化神/合体/渡劫/玄仙/太乙金仙/混元金仙/混元无极/鸿蒙道祖），`upgradeTechnique` 校验。
5. **配方炼器台等级**：`crafts` 每件补 `forgeLevel`（现行六档与丹纹佩=1；虚空/飞仙/大罗/天命套与护神佩/问道符/不朽印/归元环/太初印依次 2/3/4/5/6）；`craftEquipment` 校验。
6. **淬炼门槛**：`quenchEquipment` 按装备所属材料段校验炼器台等级与境界。
7. **收益丹凡品筑基门槛**：`craftGainPill` 凡品需筑基一层，其余按 `gainFurnaceLevel`。

**注意**：只新增门槛与费用，不清空旧档已合法获得的建筑等级/装备/丹药；已合法旧等级保留。

### P2-01 一次炼制两份库存

- `craftEquipment` 改为**只创建独立实例**（`createInstance`），不再同时写 `inventory[id]` 基础 ID；装备图鉴/背包按实例枚举（兼容旧档把基础 ID 库存归一为实例）。

### P2-02 洗髓移除共鸣中的灵根后共鸣残留

- `marrow` 在 `removeRoot` 时，若 `resonance` 指向被移除的灵根，置空 `resonance`（或按确认结果重选）。

### P2-07 schema v17→v18 落实

- `SCHEMA_VERSION` 17→18。
- `validateCommission`、`validateLastBattle` 增 `schemaVersion` 参数：`ver < 18` 允许缺新字段（合法旧档，迁移补默认）；`ver >= 18` 缺 `commission`/`lastBattle.tactic` 判为残缺新档拒绝。

## 第三批：功能与交互（P2-03/04/05/06/08）

### P2-03 委托候选/直达/确认/次日回应

- `clearedNodes` 纳入支线节点；首胜当天即时刷新候选。
- 接取后给「去完成」直达入口；领奖前加确认；回应文本在「次日」状态展示（领奖时生成但标 `respondedAt`，次日可辨认）。

### P2-04 自行设定可选灵根

- `CreateCharacter` 自行设定补灵根选择、概率说明与产速/费用/共鸣用途预览；旧档「旧式灵根」补一次免费定根迁移。

### P2-05 洗髓/功法/重铸预览与确认

- 洗髓点按钮先预览结果再确认，费用不足显示差额；功法下级费用按悟性折算显示（与实扣一致）；重铸展示新旧词条差异。

### P2-06 统一错误结构（`backend/app/main.py`）

- 注册全局 404/未捕获异常处理器，统一返回 `{"error":{"code","message"}}`，不泄露堆栈。

### P2-08 战斗入口统一战术面板

- 列表「战斗」按钮在挑战难度时也打开准备面板（同详情入口），不再绕过战术选择。
