# 全局运行复查报告

日期：2026-10-01。复查基线：`4928a9c`。本轮完成项目概览、自动检查、独立生产启动、真实浏览器主链和复查；阶段 3 整体仍不通过。本轮只补复查脚本、报告及进度记录，游戏规则与业务代码未改。

## 一、项目概览

产品是「青云修仙录」。前端使用 Next.js 15.5.26、React 19、TypeScript 和 Tailwind；确定性游戏引擎负责收益、成长、战斗与奖励，IndexedDB 保存角色进度。后端 FastAPI 代理国内模型写际遇文案，模型不控制奖励。现有内容为 200 个境界层级、21 张地图、42 个支线节点、21 个守关、19 段跨境试炼，以及洞府、装备词条、洗髓、连续际遇、战术和委托。

电脑已有 Node.js 22.23.2、npm 10.9.8、Git 2.54.0；项目后端虚拟环境为 Python 3.12.14。系统 Python 3.9.6 没有用于后端运行。

复查开始时工作区干净。原有 5185/8001 服务保留；在临时副本构建前端并使用 5186/8002 运行，以免覆盖旧构建和日常存档。5186 是同版本代码的独立验收地址，代理使用模板后端；真实模型另通过当前代码的 API 测试客户端执行。

## 四、仍未关闭的问题

### R1（P1）初始/旧装备空词条导致正常存档无法导回

- 真实浏览器复现：建新角色，不打首战，刷新到人物页，导出后原样导入，显示「导入失败：词条条数无效」。原有角色仍保留。
- 独立引擎复现：新建角色经 `migrateSave`，青铜剑成为实例且 `affixes=[]`，导回失败；代表性 v13 旧档同样失败。
- 原因：迁移按 PRD 保留空词条，但 `validateAffixList` 要求至少 1 条。位置：`engine.ts:2827` 的装备迁移及 `engine.ts:3181` 的校验。
- 边界：完成首战获得新实例的另一角色本轮导回成功，不是所有存档都必然失败。
- 修复验收：新建→刷新→导出→导入→再导出→再导入，以及旧装备迁移后同样两轮通过；保持原装备数量、基础属性和合法词条，不随机补词条来绕过。

### R2（P1）预算账本异常及并发仍能突破费用保护

`budget-review.py` 使用临时账本和假 SDK，没有联网或真实扣费。

- 损坏 JSON、数组账本均返回可继续调用；当前月值为非法字符串时抛 `ValueError`，不能降级模板。
- 并发复现：预算 0.01 元，初始累计 0.005416 元，单次估算 0.004584 元。两个线程同时进入模型调用，最终累计 0.014584 元，两个结果均为假 SDK 的 `model`。
- 已修部分：失败响应 usage 记账、SDK 不隐式重试，以及循环每次检查预算均已存在。尚未做原子费用预留；账本的线程锁只覆盖读/记账，不覆盖检查到请求之间。
- 位置：`budget.py:23/59/66`、`llm.py:94`。注释写「检查/预留」不代表实际有预留。
- 修复验收：坏账本安全降级；预算检查与预留原子化；成功、失败、异常均释放或结算预留，并验证服务重启后的费用保护。多实例能力仍留上线前专项处理。

### R3（P1）读取失败和本地坏档缺少启动恢复

- 在已存档测试来源注入 `indexedDB.open` 读取异常，刷新出现新建角色页，没有「读取失败」说明。没有点击新建，也没有宣称数据已经丢失；问题是把读取失败误显示为空档。
- 将该测试档的 `daily.goals` 删除后刷新，出现 Next.js 客户端崩溃页，无法在游戏界面恢复。注入前备份到临时文件，测试结束已原样恢复。
- 导入接口对缺 `daily.goals` 的坏档已正确拒绝，但初始化读取仍直接迁移/结算，校验及恢复没有统一。
- 位置：`game-context.tsx:189/210`、`engine.ts:2874`。
- 修复验收：区分空档、读失败、坏档；出错时保留持久化数据并提供重试、导出原档和恢复备份入口，入口不能依赖游戏页面成功渲染。

### R4（P2）委托候选未完整检查当前资源

独立真实引擎样档为炼气一层、零灵石：生成「升级一次修炼室」，可以接取，但执行返回「灵石不足」。境界/建筑等级已修，资源费用仍没纳入共用判断；战斗候选只检查首通事实，尚未验证当前挑战可胜性。位置：`engine.ts:453/518`。按 v1.8「当前可完成」要求仍需补齐筛选和条件提示；本轮不把选项失效后的自动刷新列为未修，因为前端已调用并保存刷新后的候选。

### R5（P2）端到端超时仍不一致

前端 `api.ts:43` 在 4 秒停止等待；后端默认每次 4 秒、最多两次。停止前端等待不等于取消后端模型调用，后端可能继续消耗费用。代码路径确认，未用真实模型制造超时收费。需共享总体时间预算或明确取消策略，专项验证晚返回不改变已采用模板的结果。

## 五、95 天模拟结论需要更正

旧 `simulation.ts` 在每个登录时点最多执行一次突破/跨境动作。200 层级需要 199 次晋级，每日两次自然形成约 100 天的动作限制。旧报告的「95 天」是进入第 20 境的日标，并非达到鸿蒙道祖十层的完成时间。

| 对照 | 到第 20 境的日标 | 到鸿蒙道祖十层 |
| --- | --- | --- |
| 原策略，仅补完成时间记录 | 95 天 | 100 天 |
| 原资源策略，每日两次、允许连续晋级至资源/试炼阻塞 | 23 天 | 24.5 天 |
| 同上，每日一次 | 45 天 | 47 天 |

未改任何游戏数值。24.5/47 天是对照结果，不是最终玩家体验定论：脚本仍保留原来的配装、升级、委托和战斗策略，没有在每次突破后重新执行全套可用动作；资质、经脉/悟性、灵根、冲关、长任务和战术等完整矩阵尚未补齐。旧报告将固定 5 天/境归因于低产速和材料缺口不成立，不能据此批准基础产速翻倍。应先定义有效策略与玩家行为，扩展矩阵并校准至 42～56 天目标。
