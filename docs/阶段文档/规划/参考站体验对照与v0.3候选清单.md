# 「青云修仙录」参考站体验对照与 v0.3 候选清单

> 历史候选清单：本文旧排期已由后续已确认版本及[二十境、每境十层总纲](../../PRD/PRD-修仙放置游戏-v1.2-二十境.md)更新，不再作为当前境界数量或版本顺序的依据。

> 2026-09-24 体验记录。参考站：[云隐修仙录](https://yunyin.wenzi.games/#/welcome)。本文件供产品经理筛选；[v0.3 PRD 待审阅稿](../../PRD/PRD-修仙放置游戏-v0.3.md)已按推荐范围形成，尚未启动开发。

## 体验范围与判断基线

我在参考站走过欢迎页、隐私确认、角色创建、修炼与一次小进阶、历练出发与际遇选择、背包装备与丹药、炼丹、人物属性、洞府建筑、设置及修仙录；并对照本项目本地运行的五个入口、[v0.2 PRD](../../PRD/PRD-修仙放置游戏-v0.2.md) 和对应前端实现。参考站内容规模很大，本记录只对实际看到的页面和路径负责。

本项目已有五入口、确定性战斗、镇压、四种建筑、两本功法、装备、五波天劫预览、本地存档与导入导出、离线结算、AI 际遇与模板降级。这些是已有能力，不应在 v0.3 中冒充新增。

## 建议放进 v0.3 的交互改进

| 编号 | 参考站实际看到的做法 | 本项目当前情况 | 建议的 v0.3 行为 | 优先级 |
| --- | --- | --- | --- | --- |
| A1 | 手机宽度内统一放置页头、正文与底部五入口；修炼页有清晰的主卡、进度条和唯一主操作。 | 正文限制 560px，底栏背景和边线铺满桌面；修炼页多个文本卡片层级接近。 | 页头、正文、底栏共用同一宽度和视觉网格；修炼页突出当前境界、距下境进度和主按钮。手机窄屏操作不遮挡。 | 必做 |
| A2 | 洞府首页用“下一步”与修行志告诉玩家目前该去哪里，并显示达成奖励。 | 首页直接进入修炼；新玩家需自己在五页间寻找路径。 | 只做一次性的首玩目标卡，沿用 v0.2 已定四步：领收益、小进阶、首战并镇压、查看劫势。完成后收起，不引入每日任务或额外货币。 | 必做 |
| A3 | 修炼速度可点开“来路”，显示基础值及功法、建筑等加成。人物页属性也可查看来源。 | 顶部显示待领资源，功法显示倍率，但玩家看不出实际每秒产出和加成来源。 | 修炼页展示实际修为、灵气产速；点开可见基础值、建筑、功法的计算明细，数据与引擎共源。人物页攻防气血可显示装备贡献。 | 必做 |
| A4 | 突破前能看到进度、消耗与结果；成功后单独展示境界变化。建筑与丹药明确写出效果和成本。 | 小进阶、功法升级、预置丹药等按钮在条件不足时仍可点，失败后才给提示；成功多为顶部一句通知。建筑费用已有提示。 | 对所有关键操作统一做到点击前显示条件与缺口；不能执行时禁用并说明原因；完成后显示“消耗了什么、得到了什么、下一步做什么”。保留现有筑基天劫逐波预览。 | 必做 |
| A5 | 历练地图写明适宜境界、风险、产出及镇压状态；出发前还有行程选择。 | 当前节点主要显示名字和战斗按钮，没有敌方能力、首通/重复奖励和镇压速率。 | 先给每个现有节点加详情：敌人攻防气血、首通和重复奖励、可否取胜的确定性预估、镇压每小时收益及解锁条件；战斗仍为即时战斗，不引入行程计时。 | 必做 |
| A6 | 历练途中和结束后都能看到胜场、际遇和所得；际遇选择后有独立结果页，写出实际奖励。 | 战报在页面下方；AI 际遇选完直接关闭，顶部只说“奖励到账”。 | 战后将胜负、奖励、首次解锁、失败短板放在可见结果面板；际遇选完显示引擎结算的准确奖励及故事结果，再由玩家继续。战报保留可展开。 | 必做 |
| A7 | 装备按部位查看，详情给属性、当前穿戴状态与下一动作。 | 背包是装备列表，属性已显示，换装后的实际攻防气血变化不直观。 | 维持现有三装备位和固定装备；选装备时对照“当前 → 穿上后”的属性差值，已穿戴项明确标识且不出现可点击的“穿戴”。 | 建议 |
| A8 | 设置页显示存档版本、上次导出时间、导入导出和清档；欢迎页先解释本地存档及隐私。 | 已有导入导出、重置与访问码，但没有备份时间、本地存档提示和独立设置区。 | 首次进入以短说明讲清本地存档、换设备需导出；设置显示存档版本与最近备份时间，导入/重置说明影响。隐私说明须准确写明 AI 际遇会发送最少上下文至国内模型。 | 建议 |
| A9 | 有日夜模式、减少动效与战报速度。 | 当前只有单一视觉主题，没有相关偏好设置。 | 至少增加减少动效和浅/深色模式，偏好只存本地；战报若增加播放过程，再提供跳过或速度选择。 | 建议 |

## 可作为 v0.3 增强项，由你挑选

| 编号 | 候选 | 价值与边界 |
| --- | --- | --- |
| B1 | 随机道号按钮与更有氛围的创建角色页 | 降低起名门槛。保留 v0.2 的五行灵根同强度、自选且无隐藏差距，不复制参考站的随机资质倍率。 |
| B2 | “我的修仙录”轻量记录页 | 从现有修行记录中整理首次突破、首通、镇压、渡劫和重要际遇，形成个人时间线。只记录引擎已发生的事实；AI 传记继续按原计划放在后续版本。 |
| B3 | 已解锁内容的小图鉴 | 收录见过的地图、敌人、装备、功法及其来源，给成长一个可回看的目标。只覆盖当前有限内容，不照搬参考站数百条图鉴。 |
| B4 | 洞府与地图的世界观短文案 | 用少量准确、易读的半文半白文字增强氛围。引典需核实；不增加新规则。 |

## 建议暂缓，避免 v0.3 失焦

| 参考站功能 | 暂缓原因 |
| --- | --- |
| 随机灵根资质、修炼倍率、概率小进阶 | 会改变 v0.2 已定的公平开局与固定成功规则，需重做平衡与存档。 |
| 30 分钟至 2 小时的持续历练、多档风险、临时增益、闭关倒计时 | 会引入可中断的长任务状态、恢复规则和新的离线/在线结算；目前即时战斗链路尚待正式验收。 |
| 每日任务、天气与星象加成、镇压复聚 | v0.2 明确留到后续；先验证首玩目标和核心资源经济。 |
| 九装备位、随机词条、强化分解、复杂炼丹技艺、流派 | 内容量和数值组合远超当前“炼气到筑基”闭环，容易掩盖交互问题。 |
| 师承、道侣、灵兽、寿元与轮回 | 属于长期世界和二期内容，需独立设计，不宜直接移植。 |

## 暂缓功能的建议开发顺序

这里的版本号是排期建议，不是已确认的交付承诺。v0.3 先处理已选定的交互与首玩体验；完成阶段 3 验收和小范围试玩后，根据玩家实际卡点确定后续范围。每轮只增加一组能独立验收的规则。

| 建议时点 | 功能 | 开始前要先验证什么 |
| --- | --- | --- |
| v0.4，首轮试玩后 | 每日任务、天气与星象加成、镇压复聚 | 先看玩家是否能完成首次筑基、是否愿意回访，以及当前资源产出是否稳定。每日任务需是可选目标，不变成强制打卡。 |
| v0.5，存档恢复验收后 | 30 分钟至 2 小时的持续历练、多档风险、临时增益、闭关倒计时 | 先做并验证“开始、离开、刷新、回来、结束”的持久化任务闭环；不能让计时器只活在页面内。 |
| v0.6，成长内容扩充时 | 随机灵根资质、修炼倍率、概率小进阶 | 单独做平衡方案与旧存档兼容方案，并通过试玩确认随机差异能带来选择，而非迫使玩家反复刷开局。是否采用随机资质仍需产品经理另行确认。 |
| v1.1，筑基后的境界和地图扩充时 | 九装备位、随机词条、强化分解、复杂炼丹技艺、流派 | 先有足够的敌人、掉落和资源用途，再逐个开放装备成长与炼丹，不一次塞进全部系统。 |
| 二期，长线成长验证后 | 师承、道侣、灵兽、寿元与轮回 | 先让一世角色有足够长的成长、结局与记录，再设计关系系统和轮回保留规则。各系统需独立评估，不保证同版完成。 |

上线和版本号不必强行绑定：若 v0.3 已让首次筑基体验可理解、可完成，就先做小范围试玩；后续内容依据试玩结果排序。
