# 「青云修仙录」v1.1 竞品参考与范围建议

> 历史研究说明：下文描述 v1.0.2 时的金丹一层上限。2026-09-27 新确认的[二十境、每境十层 PRD](../../PRD/PRD-修仙放置游戏-v1.2-二十境.md)已取代该长期上限；竞品观察仍作为 v1.1 当时的研究记录。

> 2026-09-26 研究记录。以下是从作品公开介绍推导的设计启发，并非对这些游戏内部数值、留存效果或玩家偏好的验证。v1.1 范围仍待产品经理确认。

## 当前版本的缺口

v1.0.2 已有突破至金丹一层、三处秘境、炼器、图鉴和事实型修仙录。金丹一层是当前境界上限，修炼页会提示“已至本版最高境界”；人物页只按时间倒序列出修仙录，没有一个可回看的阶段目标与阶段回顾。若直接加入寿元或轮回，玩家还没有可辨认的“一世完成了什么”。

v1.0.2 本地复核结果：前端 137/137、后端 18/18 测试通过；类型检查和生产构建通过；Lint 通过并有一条 Hook 依赖警告。真实玩家试玩、物理真机、正式部署及新的真实模型调用依产品经理决定留到最终总体验收。生产环境的共享限流与 postcss high 依旧是上线前待办，不作为本地起草 v1.1 的阻塞。

**本轮补上的导入校验：** 复核发现 `importSave` 只检查 `milestones` 是否为数组，未逐条验证 `type/time/text`。例如原先 `milestones: [null]` 可通过导入校验，人物页读取记录时可能报错。现已补逐条校验，同时校验最近修行记录和首玩标记；畸形存档回归用例通过，前端测试升至 138/138。v1.1 展示仍需继续使用有结构化依据的事实字段。

## 建议写进 v1.1 PRD 的范围

**推荐：金丹篇章目标 + 事实型阶段回顾。** 进入金丹一层后，人物页可查看本篇章的三个既有成果：结丹、秘境探索、炼器。玩家可看到各项是否达成及未达成项的去处；完成状况由现有存档事实计算，不发奖励、不封档、不强迫炼器。回顾按实际记录整理角色名、资质、突破、首通、秘境、制作等经历，缺记录就说明未收录。它是“当前版本篇章”，不是一生结局。AI 传记只在事实和费用边界、真实样例都能验证后另立需求。

这个切片解决当前上限无目标的体验缺口，复用已经有的状态和修仙录，且能为未来师承、道侣、寿元与轮回提供事实基础。开发时首先核对既有结构化记录能否可靠判断每个成果；缺证据的项不得从文案猜测。既有数据足够时不升存档版本；若新增持久字段，则按开发自检清单处理旧档、坏档及多标签并发。

## 后续单独规划

1. **师承或灵兽**：参考《鬼谷八荒》的关系与成长，但先选一种关系做小闭环，明确互动频率、资源来源、离线推进、离开关系的代价及旧档兼容，再决定是否进入开发。
2. **AI 传记**：只能压缩真实修仙录，不能凭空补写行为、战果或奖励；需模型输出结构校验、超时与费用上限、真实样例评审。由于本轮真实环境验证后置，暂不合入 v1.1。
3. **寿元与轮回**：参考《太吾绘卷》的传承思路，但须先确定真正的一世终点、保留物、清零项、导入导出和玩家确认流程；现有“新开一局”不能改名冒充轮回。

## 进入开发的条件

- 产品经理确认 v1.1 的单一范围与“不新增模型调用、不做轮回”的边界。
- 既有修仙录导入校验已在本轮补齐；开发时继续验证旧档事实缺失的显示方式。
- 开发文档逐条核对结丹、秘境、炼器及修仙录字段，明确旧档缺少历史时如何呈现。
- 本地自动化、类型检查、构建、浏览器关键路径和存档兼容仍按阶段闸门提交；真人试玩、物理真机、真实模型和正式上线待最终总体验收，并保持“待验”标记。
