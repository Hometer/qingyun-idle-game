# 独立验收修复方案（A1～A4、B1～B4）

> 依据 `docs/阶段文档/独立验收-2026-10-01/独立验收报告.md`（基线 `f9af9e0`）。先修 A1/A2 存档与恢复，再修 A3/A4 奖励与费用保护，再补 B1～B3，最后复核成长统计与下载文件。

## A1 坏档覆盖健康备份 + 恢复后卡错误页

- 坏档启动校验失败后**不再调用 `backupSave`**（避免把健康备份写成坏档）；只记录 `loadError` 并保留原档供「导出原档」。
- `doRestoreBackup`：恢复前用 `validateSaveObject` + `migrateSave` 校验/迁移备份，失败则显示在恢复页（`loadError`），成功则写入、更新 revision、清 `loadError` 并 `setState`。
- 复验：先存健康备份→坏当前档→刷新（备份完好）→恢复→直接回到游戏（不再卡错误页）；恢复失败信息可见。

## A2 缺 revision 永久冲突

- `validateSaveObject`：`ver >= 18` 时校验 `revision` 为有限非负整数，缺失/非法拒绝。
- `migrateSave`：旧档（`ver < 18`）缺失 revision 时补 0（确定性）。
- 复验：v18 缺 revision 进恢复提示；v17 旧档迁移后正常保存、不再 `NaN` 冲突。

## A3 委托时间回拨

- `acceptCommission`：把 `acceptedDate === today` 改为高水位 `today <= acceptedDate`（回拨日期不得接取）。
- 复验：day2 接取领奖→回拨 day1 首通→不能再接；跨日未完成仍可完成一次；导出导入通过。

## A4 预算 NaN/负数 + usage 缺失

- `budget._read_spend`：`float()` 后校验 `math.isfinite && >= 0`，否则返回 `inf`（失败关闭）。
- `llm.py`：usage 缺失但调用已发出时，`settle(estimate, estimate)` 保守按预留上限记账，不当免费。
- 复验：账本 NaN/负数/非法月值均 blocked；成功但无 usage 记预留值，不再记 0。

## B1 端到端总截止时间

- `llm.py` 增加总时间预算（默认 3.5s，`settings.model_total_budget_seconds`），每次尝试前检查剩余时间，截止后不再发起新重试。
- 复验：慢速分段假 API 下，完整调用不再超过前端 4s 太多；截止后不再有第二次调用。

## B2 委托候选可接/两件/直达

- `battleCandidate` 改为遍历已通关节点，选**当前挑战可胜**的目标；不再生成不可接候选。
- `craftCandidate` 无可负担制作时，回退为「领取 1 次收益」（新动作 `settle`，始终可完成），保证与战斗候选构成两件不同目标。
- `commissionCompletable`/进度钩子补 `settle`；历练页补「去完成」直达入口。
- 复验：新角首胜后有两件不同候选；高境界不可胜候选不再生成；接取后有直达。

## B3 矛盾委托进度可导入并领奖

- `validateCommissionItem`：`status ∈ {ready, claimed}` 时强制 `progress >= target`；`accepted` 时 `progress < target`；`actionParam` 对照固定配方/建筑/功法校验；`claimCommission` 领奖前再查 `progress >= target`。
- 复验：`ready` 但 `progress=0` 的档拒绝导入；未知动作参数拒绝；重复领奖被拦。

## B4 成长汇总更正（记录，不改数值）

- 更正一次登录实际 39～52 天（18 组 <42），随机冲关修正「失败后当次可重试」后 54 组 40～48 天；不擅自调产速/离线，待多种子/策略与真人校准。本轮只更正报告与状态，不改数值。
