# 第 2 阶段技术开发文档｜后端 MVP（核心链路）

> 配套文档：`docs/PRD/PRD-修仙放置游戏-v0.2.md`、`docs/手册/AI产品Vibe Coding通用技术栈手册.md`、`docs/阶段文档/阶段1-技术适配/技术适配声明.md`。
> 本文档只覆盖第 2 阶段。开发时不得提前实现阶段 3 的正式前端视觉与其他阶段能力。

## 一、阶段目标

- 交付范围（对齐 PRD 3 节 P0）：
  1. 确定性游戏引擎（TypeScript 纯状态机）：时间结算、小进阶、历练战斗与镇压、洞府建筑、功法与装备、护劫丹、天劫、存档 schema 与离线结算、导出/导入/重置。
  2. AI 文案代理后端（Python FastAPI）：3 种际遇事件 × 2 选项，结构校验、内容审核、超时、限流、模板降级，密钥只存后端。
  3. 模板库：覆盖 3 事件 × 6 分支结果，AI 不可用时仍可完成全部首版流程。
  4. mock 自动化测试（Vitest + pytest）+ 真实模型冒烟。
  5. 最小验收界面（临时，不复用为正式前端）。
- 阶段产物：一条可运行的核心链路——创建角色 → 领取挂机收益 → 小进阶 → 历练首通 + 镇压 → 触发际遇（AI 或模板）→ 渡劫预览。
- 验收标准：对齐 PRD 7.2 场景 1（完整首玩，窄屏可操作）、2（经济一致）、3（离线结算）、4（天劫恢复）、5（AI 降级）、6（存档安全）与 7（文案质量，人工判断）；体验目标见 PRD 7.1（首次筑基 45~75 分钟为调参基线，不是硬指标）。
- 明确不做：正式五入口界面与视觉（阶段 3）、账号/PVP/内购、P1/P2 系统（藏经阁、炼器台、灵兽园、辅修功法、妖气复聚、传记、轮回、NPC 对话等）。
- 本阶段打通的主链路片段：`创建角色 → 时间结算 → 小进阶 → 历练首通/镇压 → 际遇（AI/模板）→ 渡劫预览`。

## 二、技术适配摘要

- 结论引用：见 `docs/阶段文档/阶段1-技术适配/技术适配声明.md`。核心判断——业务核心（游戏引擎）跑在浏览器端，后端仅为薄 AI 代理；采用**纵向切片**路径。
- 本阶段采用默认方案：Python 3.12 + FastAPI + Pydantic（后端）；TypeScript + React 默认栈的引擎部分（本阶段只用 TS 纯引擎，React/Next.js 留阶段 3）。
- 本阶段启用按需模块：最小验收界面（文案与渡劫预览需"用眼睛看"）。
- 本阶段偏离/暂缓：正式前端五入口推迟到阶段 3；最小界面用 Vite + 原生 TS（比 Next.js 更轻，仅作验收工具，引擎纯 TS 可被阶段 3 复用）。
- 开发路径：纵向切片。

## 三、技术栈与模型

| 组件 | 选择 | 说明 |
| --- | --- | --- |
| 游戏引擎 | TypeScript + Vitest | 纯状态转换，可复现、可单测 |
| 最小界面 | Vite + 原生 TypeScript + HTML | 临时验收工具，不引入 React |
| AI 代理后端 | Python 3.12 + FastAPI + Pydantic | 薄代理，不含玩家存档 |
| 后端测试 | pytest | mock 模型调用 |
| 模型 | 国产 OpenAI 兼容接口，默认 `deepseek-chat`；可切 `glm-4-flash` / `qwen-plus` | D4 已定国产；通过 `MODEL_API_BASE`/`MODEL_NAME` 配置，不硬编码 |

明确不引入：数据库（SQLite/SQLAlchemy/Alembic）、RAG、文档/OCR、任务队列、SSE（文案一次性返回）、对象存储。

## 六、数据、资产与状态

- 持久化：玩家存档存浏览器 **IndexedDB**（`schemaVersion` 字段），引擎以纯函数 + 事务式提交变更（先算后写，刷新不重复结算）。后端**不持久化**玩家数据。
- 存档字段（对齐 PRD 6.1）：`schemaVersion`、角色 ID、角色资料（姓名/灵根）、资源（修为/灵气/灵石/灵草/残页）、境界、功法/装备/建筑等级、地图与镇压状态、已触发事件、待结算事件、最近修行记录、`lastSettledAt`、修订号。
- 状态机：境界（炼气一层→二层→三层→圆满→筑基一层）；节点（未解锁/可挑战/已首通/已镇压）；际遇（待选择/已完成）；渡劫（待结算事件，防刷新双扣）。
- 数值全部集中 `src/engine/config.ts`，展示与计算同一来源，标记"可调基线"。

## 七、API 设计

`POST /api/v1/encounter/generate`

- 请求体：
  ```json
  {
    "event_id": "event_well",
    "character": { "name": "林青", "realm": "炼气二层", "spirit_root": "金" },
    "map_id": "map_qingyun",
    "options": [
      { "option_id": "well_a", "label": "探查井底", "meaning": "冒险下井一探" },
      { "option_id": "well_b", "label": "绕行而去", "meaning": "不理会，绕路离开" }
    ],
    "recent_logs": ["首次通关青云山·野狼", "于古井旁发现异光"]
  }
  ```
- 响应体（模型成功或模板降级，结构相同）：
  ```json
  {
    "source": "model" | "template",
    "event_id": "event_well",
    "title": "古井奇遇",
    "body": "……半文半白文案……",
    "options": [
      { "option_id": "well_a", "option_text": "下井一探" },
      { "option_id": "well_b", "option_text": "绕路离开" }
    ]
  }
  ```
- 错误（统一结构，不泄露堆栈）：
  - `422` 请求结构非法：`{"error":{"code":"INVALID_REQUEST","message":"..."}}`
  - `429` 触发限流：`{"error":{"code":"RATE_LIMITED","message":"..."}}`
  - `403` 邀请码不符：`{"error":{"code":"FORBIDDEN","message":"..."}}`
  - `500` 未预期错误：`{"error":{"code":"INTERNAL","message":"服务暂时不可用"}}`
- 说明：本阶段文案一次性返回，不用 SSE，故无流式事件约定；奖励/数值一律由引擎本地按配置结算，后端响应不返回任何奖励字段。

## 八、Prompt 设计

- 角色：修仙题材叙事作者。
- 输入变量：事件原型设定、角色称呼/灵根/境界、地点、最近两条修行摘要、两个选项含义。
- 输出格式：严格 JSON（`{"event_id","title","body","options":[{"option_id","option_text"}]}`），Prompt 内给正反例（禁止输出编号、奖励、属性数值、与分支冲突的收益暗示）。
- 约束：半文半白、易读、可适度引典籍但不得杜撰出处、不血腥猎奇、不得承诺与配置冲突的结果。
- 解析与校验：后端确定性 JSON 解析（宽容兼容）→ Pydantic 强校验（事件 ID 一致、选项 ID 集合完全一致、长度范围、占位符）→ 内容审核（违规词、冲突收益暗示）→ 失败走模板降级。

## 十、测试要求

第一层 mock 自动化测试（离线可跑）：

- 引擎（Vitest）：时间结算（含 12h 上限、负时间差归 0、不重复结算）、小进阶门槛与扣费、战斗伤害公式 `max(1,攻-防)` 与先手顺序、首通/重复奖励、镇压切换、建筑/功法升级即结算、天劫五波与减伤上限 40%、护劫丹第三波回 30%、渡劫刷新不双扣、存档导出/导入/损坏拒绝、经济一致性（相同输入相同结果）。
- 后端（pytest）：模型返回结构非法→422 或降级、事件/选项 ID 不匹配→降级、超时→降级、限流 429、邀请码 403、违规内容→降级、统一错误结构。

第二层真实模型冒烟（阶段验收前，需真实 Key）：

- 用真实 Key 跑通 `POST /encounter/generate`：3 种事件各至少 1 条真实文案，记录来源（首测/重试后合规）、延迟、token 用量、成本。无 Key 时如实标注"待验"，不用 mock 冒充。
- D2 验收标准按手册第十节"Agent 效果默认评分法"，用 5~10 条真实样例请产品经理打分后写入台账。

## 十一、验收清单（产品经理照着点）

- [ ] 打开验收页，创建角色（填姓名、选灵根），看到初始资源。
- [ ] 点"领取挂机收益"，资源增加；刷新页面，同一时段收益不重复领取。
- [ ] 修为/灵气达标后点"小进阶"，境界提升、资源按门槛扣除，成功率 100%。
- [ ] 进入地图1，击败并镇压第一个节点，看到镇压产出。
- [ ] 触发一次际遇，看到半文半白文案（有 Key 为 AI 文案、无 Key 为模板），选择选项后奖励到账。
- [ ] 炼气圆满后查看渡劫预览，五波伤害、减伤来源、丹药、预计结果与 PRD 4.5 一致。
- [ ] 导出存档→重置→导入，进度恢复；导入损坏文件不覆盖当前存档。
- [ ] 手机窄屏下核心按钮可点可用。

## 十二、风险与待确认项

- 首轮数值（建筑/功法/装备/节点/奖励）为"可调基线"，首次筑基 45~75 分钟需试玩验证，偏离则先调 `config.ts`。
- 内容审核为确定性规则（关键词 + 冲突收益暗示），深度语义违规需真实样例复检；不承诺 100% 拦截。
- 限流为单进程内存态，多实例部署时需换共享限流（阶段 4 上线前处理）。
- 需产品经理决定的问题：无（D2 待冒烟打分、D9 待阶段 4、D4 成本上限暂记 100 元/月，均不阻塞本阶段）。
