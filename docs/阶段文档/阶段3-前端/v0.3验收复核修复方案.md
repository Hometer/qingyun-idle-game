## 关键实现说明

- **V03-03 假冲突根因**：`apply()` 用修订号 CAS；失败动作把未变的 `state` 交给 `apply`，`revision` 未增，被 CAS 判为冲突。修复：失败分支只 `setNotice(reason)` 并 return，不写库。
- **V03-04 增量隔离**：所有产生回执的动作先 `eng.settle(state, now)` 得到 `settled`，再执行动作，`deltaLines(settled, result)` 只含动作自身的消耗/奖励，不含时间收益。
- **V03-05 时序**：`const ok = await apply(next, msg); if (ok) setLastResult(...)`，持久化成功才弹回执。
- **V03-06 还原**：迁移 v1 档时 `suppressedFirstNodeOnce` 取 `suppression.map_qingyun === 首个节点`；`breakthrough` 目标由 `realm` 派生已正确。
- **V03-07 旧档说明**：localStorage `qingyun_notice_shown` 缺省时，加载旧档后显示一次性说明弹层，明确选择 AI/模板后再继续。

## 验收标准
1. 迁移旧档前产生可恢复备份；导入前确认、备份失败不覆盖。
2. 资源不足时按钮禁用并显示缺口；点击不再出现假冲突提示。
3. 战斗/际遇/进阶/渡劫回执只列本次操作的实际消耗/奖励与选项，不含挂机收益；回执在持久化成功后出现。
4. 旧档迁移后"击败并镇压首个节点"按已有镇压事实标记；炼气圆满前天劫目标只显示"后续目标"、不给直达。
5. 旧档首进显示数据说明与 AI/模板选择。
6. 底栏与正文同宽；人物页属性拆分、修仙录带奖励、图鉴有来源与占位；灵气 0.25 显示准确。
7. 新增自动化测试覆盖迁移备份、失败路径、增量隔离；`tsc`、前端 32+、后端 14 全绿、`next build` 通过；浏览器重跑上述场景。
