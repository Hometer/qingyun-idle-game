# 阶段 3 · v0.5 开发文档

> 配套：`docs/PRD/PRD-修仙放置游戏-v0.5.md`（持续历练 + 闭关，单长期任务位）。
> 本版只做长期任务，不新增境界/地图/敌人/装备/账号/模型调用。

## 1. 目标

新增一个**可离开、可刷新、可回来领取**的长期任务：持续历练与闭关共用一个任务位，30/60/120 分钟，到期由存档时间戳判定并手动领取。

## 2. 数据模型（schema v3 → v4）

`SCHEMA_VERSION` 3 → **4**。`SaveState` 新增：

```ts
type LongTaskType = "training" | "seclusion";
type LongTaskDifficulty = "steady" | "risky";

interface LongTask {
  id: string;
  type: LongTaskType;
  mapId?: MapId;
  nodeId?: string;
  difficulty: LongTaskDifficulty;
  protectionUsed: boolean;      // 护行阵
  durationMinutes: number;      // 30 | 60 | 120
  startAt: number;
  endAt: number;
  ruleVersion: number;
  snapshot: {
    playerAttack: number;
    playerDefense: number;
    playerHp: number;
    cultivationPerSec: number;  // 闭关用
    spiritPerSec: number;
    enemyAttack?: number;       // 历练用
    enemyDefense?: number;
    enemyHp?: number;
    expectedReward: Resources;
  };
}

interface LongTaskResult {
  taskId: string;
  type: LongTaskType;
  nodeName?: string;
  difficulty?: string;
  durationMinutes: number;
  reward: Resources;
  completedAt: number;
  aborted: boolean;
}
// SaveState 增：longTask: LongTask | null; lastLongTaskResult: LongTaskResult | null;
```

- 任务进行中/可领取由 `endAt` 与时间戳推导；**领取/中止结果持久化**为 `lastLongTaskResult` 并清空 `longTask`。
- `migrateSave`/`normalizeSave` 兼容 v1/v2/v3 → v4：`longTask = null`、`lastLongTaskResult = null`，其余保留。

## 3. 引擎能力

- `canArrange(state)`：是否已首镇压（解锁入口）。
- `predictLongTask(state, type, mapId, nodeId, difficulty, durationMinutes, protection)`：返回胜负预估 + 各资源预计所得（护行阵影响防御快照）。
- `startLongTask(state, nowMs, params)`：校验（入口已解锁、无在途任务、历练节点已首通且境界满足、预计可胜、护行阵灵石足够）；扣护行阵费、锁定快照、写入 `longTask`。同事务，失败不扣费。
- `claimLongTask(state, nowMs)`：`now >= endAt` 才可领取；按快照结算奖励（历练=锁定重复奖励×倍率，险行×1.5，逐项向下取整；闭关=锁定产速×时长秒×10%，保留 1 位小数），写 `lastLongTaskResult`、清 `longTask`。
- `abortLongTask(state, nowMs)`：二次确认后清空任务，奖励零、护行阵不退，写中止结果。

## 4. 奖励基线（config）

```ts
longTask: {
  durations: [30, 60, 120],
  multipliers: { 30: 2, 60: 3, 120: 5 },
  riskyMultiplier: 1.5,
  protectionCost: 30,
  protectionDefense: 5,
  riskyEnemyMultiplier: 1.25,
  seclusionRateFactor: 0.1,
}
```

## 5. UI

- 页头：有在途任务时显示摘要（类型、剩余时间、到期/可领取、中止），点击到对应页。
- 历练页：入口「安排持续历练」（已首镇压后），选节点/稳行险行/时长/护行阵，看预览后开始。
- 修炼页：入口「安排闭关」，选时长后开始。
- 结果面板：领取/中止回执（复用 v0.3 结果面板），分列任务所得与普通离线收益。
- 长期任务进行中不阻塞即时战斗/换装/建筑/渡劫等。

## 6. 子阶段

1. **子阶段 A｜引擎**：schema v4 + 长期任务状态机 + 预测/开始/领取/中止 + 迁移，引擎测试。
2. **子阶段 B｜界面**：页头摘要、历练/修炼入口与预览、结果面板。

## 7. 验收（对齐 PRD 第 5 节）

关键：开始→离开→刷新→回来→到期领取；29:59/30:00 边界；快照锁定（期间换装不追改）；任务奖励与普通离线收益分列；中止不退费；长时间离线只结一次且普通收益仍 12h 上限；v1/v2/v3 迁移、v4 在途导出导入；时间回拨与双标签。
