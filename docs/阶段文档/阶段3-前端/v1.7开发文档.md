# v1.7 开发文档：连续际遇 + 战斗反馈

> 配套 PRD：`docs/PRD/PRD-修仙放置游戏-v1.7-连续际遇与战斗反馈.md`。产品经理确认：按草案完整开发（A 连续际遇 + B 战斗反馈 两个子阶段都做，不拆分交付）。

## 1. 范围

- **A 连续际遇**：现有三条早期事件（古井奇遇 / 灵兽现踪 / 残破洞府）各增加一个后续事件；后续依玩家当初的选择分支，完成后在修仙录留下「起因—选择—回响」记录；模型失败时有完整本地模板兜底。
- **B 战斗反馈**：历练普通/挑战、守关 BOSS、秘境的战后摘要 + 可展开逐回合记录；最近一战写入本地存档，刷新/重启后可查看；查看战报绝不二次结算。

**不改变**：原始事件选项与即时奖励、每日际遇上限、伤害公式、敌人强度、掉落、每日奖励上限、挑战回合限制、六至八周节奏目标。

## 2. 数据模型（schema v16 → v17）

`types.ts` 新增：

```ts
export type StoryId = "well" | "beast" | "cave";

export interface ContinuityStory {
  storyId: StoryId;        // 故事
  originOptionId: string;  // 玩家当初的原选择（如 well_a）
  originDate: string;      // 完成初始事件的本地日期 YYYY-MM-DD
  stage: "awaiting" | "active"; // awaiting=待触发后续；active=后续已触发、待选择
}

export interface BattleRoundEvent {
  round: number;            // 第几回合（从 1 起）
  actor: "player" | "enemy";
  kind: "attack" | "crit" | "regen" | "low_hp" | "limit"; // limit 仅用于回合上限提示
  amount: number;           // 伤害或回复量
  playerHpAfter: number;
  enemyHpAfter: number;
  text: string;             // 人话一行
  key?: boolean;            // 是否为关键事件（暴击/回血/低血增伤）
}

export interface LastBattle {
  won: boolean;
  kind: "map" | "secret";          // 地图战 / 秘境战
  mapName: string;
  enemyName: string;
  difficulty: string;              // normal / challenge / secret
  maxRounds: number;
  roundLimitReached: boolean;
  rounds: number;                  // 实际回合数
  player: { attack: number; defense: number; hp: number; hpAfter: number };
  enemy: { attack: number; defense: number; hp: number; hpAfter: number };
  events: BattleRoundEvent[];      // 逐回合精简记录（有界，≤ 上限条数）
  keyEvents: string[];             // 实际发生的关键事件描述（只记真实触发的）
  rewardLines: string[];           // 实际获得奖励（人话），战败为空
  noRewardNote?: string;           // 如「本次无重复奖励」
  at: number;
}
```

`EncounterState` 增两字段；`SaveState` 增 `lastBattle: LastBattle | null`：

```ts
export interface EncounterState {
  pending: { eventId: string; mapId: string } | null;
  triggeredToday: number;
  lastTriggerDate: string;
  guideDone: boolean;
  continuity: ContinuityStory | null;  // 当前挂起的连续际遇（最多一条）
  completedStories: StoryId[];          // 已完整走完的故事（防止重复开启）
}
```

## 3. 配置（config.ts 单一来源）

### 3.1 后续事件并入 `encounters`

六条后续事件写入 `CONFIG.encounters`，**不设 `minStage`**（`randomEventId` 按 `minStage <= stage` 过滤，`undefined` 自然被排除，不会进入随机池），选项**不设 `reward`**（纯叙事）。事件 ID 与故事/原选择的对应：

| 故事 | 原选择 | 后续事件 ID | 后续两选项 |
| --- | --- | --- | --- |
| well 古井奇遇 | well_a 探查井底 | `event_well_down` | well_down_a / well_down_b |
| | well_b 绕行而去 | `event_well_around` | well_around_a / well_around_b |
| beast 灵兽现踪 | beast_a 出手相救 | `event_beast_saved` | beast_saved_a / beast_saved_b |
| | beast_b 静观其变 | `event_beast_watch` | beast_watch_a / beast_watch_b |
| cave 残破洞府 | cave_a 推门而入 | `event_cave_enter` | cave_enter_a / cave_enter_b |
| | cave_b 记下位置 | `event_cave_note` | cave_note_a / cave_note_b |

共 3 故事 × 2 原选择 × 2 结局 = **12 条结果路径**。

### 3.2 连续际遇映射

`CONFIG.continuity`：

```ts
continuity: {
  stories: {
    well:  { originEventId: "event_well",  followUps: { well_a: "event_well_down",  well_b: "event_well_around" } },
    beast: { originEventId: "event_beast", followUps: { beast_a: "event_beast_saved", beast_b: "event_beast_watch" } },
    cave:  { originEventId: "event_cave",  followUps: { cave_a: "event_cave_enter", cave_b: "event_cave_note" } },
  },
},
```

### 3.3 战报上限

`CONFIG.battleReport = { maxEvents: 120, maxKeyEvents: 20 }`（逐回合与关键事件有界，防存档膨胀）。

## 4. 引擎改动（engine.ts）

### 4.1 `runBattle` 结构化

返回从 `{ won, log }` 扩展为 `{ won, log, rounds, keyEvents, roundLimitReached }`，逐回合记录 `BattleRoundEvent`（`log` 保持不变，兼容现有 UI）。关键事件只在实际触发时记录：
- `regen > 0` 且实际回血 > 0 → kind "regen"，key=true
- `rng() < critRate` 触发暴击 → kind "crit"，key=true
- 低血增伤（`pHp < hp*0.3` 且 `lowHpBoost>0`）→ kind "low_hp"，key=true
- 达回合上限仍不分胜负 → kind "limit"

现有调用方（`fightNode`/`predictFight`/`enterSecretRealm`/`predictSecretRealm`/测试辅助）只读 `won/log`，不受破坏。

### 4.2 连续际遇触发（`fightNode` 胜利后）

优先级：古井新手引导（首次首通野狼，保持）→ **连续际遇后续** → 随机际遇。

```ts
const cont = s.encounter.continuity;
if (cont && cont.stage === "awaiting" && todayStr(nowMs) > cont.originDate) {
  if (s.encounter.triggeredToday < CONFIG.encounter.dailyMax) {
    triggerEncounter(s, mapId, followUpEventId(cont));
    cont.stage = "active";
    encounterTriggered = true;
  } // 额度满：保留，不触发任何际遇
} else if (rollEncounter(s, nowMs)) {
  triggerEncounter(s, mapId, randomEventId(s));
  encounterTriggered = true;
}
```

新增守卫：`fightNode` 开头若 `s.encounter.pending` 已存在（旧际遇未处理），不再触发新际遇（防覆盖、防重复结算，PRD 3.1.5）。

### 4.3 际遇结算（`resolveEncounter`）

- **初始事件**：`eventId` 为三条起源事件之一，且 `s.encounter.continuity === null` 且 story 不在 `completedStories` → 记录 `continuity = { storyId, originOptionId, originDate, stage: "awaiting" }`。奖励照旧发放。
- **后续事件**：`eventId` 为六条后续事件之一（对应 `continuity.stage === "active"`）→ 不发奖励，`completedStories.push(storyId)`、`continuity = null`，并 `pushMilestone(s, "continuity", nowMs, ...)` 记录「起因—选择—回响」。
- 其余照旧。奖励字段从必填改为可选（后续事件无奖励）。

### 4.4 战斗反馈写入

`fightNode` 与 `enterSecretRealm` 在结算后构造 `LastBattle` 写入 `s.lastBattle`：
- 双方数值、胜负、实际回合数、是否达回合上限、逐回合 events、keyEvents；
- 奖励行：首通（含装备/功法/材料）或重复奖励；重复额度用尽时 `noRewardNote = "本次无重复奖励"`；战败 rewardLines 为空、`noRewardNote = "未获得奖励"`。
- 战败时 keyEvents 附 `analyzeFailure` 的短板结论作为下一步建议。

### 4.5 迁移与校验

- `SCHEMA_VERSION` 16 → 17。
- `createGame` 默认 `continuity: null, completedStories: []`；`migrateSave` 补默认（同时补 `encounter` 对象缺失的兜底）。
- `importSave`/`validateEncounter` 增加：continuity 结构合法、completedStories 为合法 StoryId 数组、`lastBattle` 结构合法且 events/keyEvents 长度有界；无效新字段拒绝导入（现档不变）。

## 5. 后端改动

- `fallback.py`：新增 6 条后续事件模板（title/body/options），文案必须承认玩家原选择（下井者不写成亲眼看过井外、救鹿者才得靠近回应等）。
- `schemas/encounter.py`：`GenerateRequest` 增可选 `context: str | None`（后续事件的「情境提示」，如“此前你在古井奇遇中选择了探查井底”），用于让模型承认原选择。
- `llm.py`：`_build_prompt` 在有 `context` 时追加一行情境提示；其余（超时/重试/结构化/审核/模板降级）不动。
- `moderation.py`：不改（后续事件同样禁止收益暗示与数值）。

- `game-context.tsx`：
  - 际遇加载 effect：后续事件带 `context` 请求；`choose` 与 `localTemplate` 适配无奖励的后续事件。
  - `fight`：胜利后展示摘要 + 逐回合战报（读 `r.state.lastBattle`）。

## 7. 测试

新增/修改 `engine.test.ts`（或新 `v1.7-continuity.test.ts`）覆盖：

**A 连续际遇**
1. 首通野狼触发古井引导，选 well_a 后 `continuity` 记 awaiting；同日再胜不触发后续（`originDate` 同日）。
2. 次日（`T0 + 24h` 后）再胜优先触发后续（pending 为 `event_well_down`），`stage` 变 active。
3. 后续占用一次额度、不发奖励；选择后 `completedStories` 含 well、`continuity` 清空、修仙录新增 continuity milestone。
4. 额度满时后续保留，不触发；旧待处理际遇未处理时不再触发新际遇。
5. 已完成的 story 再次出现同起源事件 → 只作普通际遇，不重开故事。
6. 12 条路径（3 故事 × 2 原选择 × 2 结局）各能走通、记录正确；其他 origin option 走对分支。
7. 旧档迁移（v16）→ continuity/completedStories 默认空、lastBattle 默认 null；坏 continuity/lastBattle 档拒绝导入。

**B 战斗反馈**
1. 胜负各一场：`lastBattle` 的 won/回合数/双方剩余气血/奖励行正确。
2. 12 回合挑战 BOSS 达上限：`roundLimitReached` 为真。
3. 重复奖励用尽：`noRewardNote` 为「本次无重复奖励」。
4. 可控场景验证「真实触发才记录」：暴击/回血/低血增伤在触发与不触发两种输入下 keyEvents 正确（用固定 rng 种子）。
5. 秘境战 lastBattle.kind = "secret"；最近一战刷新/重启后从 `state.lastBattle` 读取，查看不重复结算。

## 8. 验收（对应 PRD 第 7 节）

- A：三条故事 12 条路径可走通；触发时机（次日优先、额度满顺延、待处理优先、只占一次额度）符合规则；模型与模板两条路都能完成；刷新/重启/旧档迁移/导入导出后状态不丢、不复制。
- B：历练普通/挑战/守关/秘境各至少一场胜负核对摘要与逐回合；暴击/回血/减伤/低血增伤真实触发才显示；最近一战可恢复、下一战替换、查看不重复结算；390px 与桌面可读、键盘可展开。
- 闸门：前端测试 + typecheck/lint/build 通过；真实模型冒烟按 AGENTS.md 记录（无 Key 时写「待验」，不冒充通过）。
