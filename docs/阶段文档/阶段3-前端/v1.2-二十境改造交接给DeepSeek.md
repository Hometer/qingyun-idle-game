# 给 DeepSeek 的境界改造交接

> 2026-09-27。先读根目录 `AGENTS.md`、`docs/项目状态.md`、[v1.2 PRD](../../PRD/PRD-修仙放置游戏-v1.2-二十境.md)与[开发自检清单](../开发自检清单.md)。这是文档交接，当前代码尚未按二十境改造；不要把本文件写成已验收结果。

## 产品经理已经定下的范围

- **20 个大境界，每境一至十层，十层即圆满；只在十层且满足条件后由玩家主动突破至下一境一层。** 完整名称与顺序以 v1.2 PRD 第 3 节为准。当前代码的金丹一层上限须逐段延伸。
- 旧“四界二十一境”总数已被本次二十境取代；四界分界和名称没有可靠资料，不要自行补世界地图或付费/在线系统。
- 真人试玩、物理真机、正式部署与新增真实模型验证留最终总体验收；本地程序模拟、自动测试、浏览器检查、旧档迁移和证据包照常完成。

## 请先交付可复核的实施设计

1. 列出 `RealmId`、配置、进阶与跨境试炼、地图门槛、人物/修炼/篇章页、存档校验和导入迁移中依赖现有 8 个境界的位置。标明 200 层目标下哪些逻辑可配置化、哪些历史规则要保留。
2. 给旧 v1～v9 存档的完整映射表，特别是旧炼气二/三层和筑基二层；比较迁移前后属性、地图开放、资源和长期任务快照。旧炼气/筑基圆满对应新十层，金丹一层不回档；不能伪造旧突破记录。
3. 先模拟首轮开发周期的三资质与稳妥/冲关路径，提出实际可达的成本、属性、地图节点与“金丹十层→元婴一层”试炼规则。成本、预览、结算和测试读取同一配置。不要把无内容的后续境界开放成可点进阶按钮。
4. 将二十境总目标拆成连续可验收的子阶段：A 旧境十层化与迁移，B 金丹二至十层和历练，C 元婴入境试炼；每段补玩法内容、自动检查和证据包，再开放下一段。不得宣布 200 层已经可玩，除非全部段落均有内容且通过闸门。

## 必须保留与必须验证

- 保留现有功能、数据、旧战报与 v1.1 金丹篇章；篇章是阶段记录，不是寿终或轮回。AI 只负责叙事，不决定突破成功、消耗、掉落和奖励。
- 旧档导入先校验与备份；坏档拒绝、失败不覆盖；双标签同一突破只成功一次；刷新/关闭重开后结果一致；在途长期任务按启动时快照结算。
- 小进阶的稳妥/冲关保底、跨境的人工确认与预览、失败代价，按 PRD 对齐。九层不能跨境；十层不自动晋级；第二十境十层给准确的当前规划终点提示，不自动清档。
- 每段交付前跑前后端既有测试、类型检查、Lint、生产构建，并补境界顺序、边界层、迁移、坏档、并发、数值可达与窄屏测试。真实环境项目未做时写“待验”。

## 需要回报产品经理的结果

用产品语言说明本轮**实际开放到哪一境哪一层**、新增的历练与突破玩法、旧存档如何接续、程序模拟用时及未验证的体验；附 `docs/evidence/` 中的阶段闸门表和可自行核对的页面步骤。不要以“配置里列出了二十境”代替可玩验收。
