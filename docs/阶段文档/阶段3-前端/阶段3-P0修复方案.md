## 逐项说明

### P0-1 功法入口
- 修炼页「境界」下方新增「功法」区：
  - 当前主修（无则显示"无"）；两本功法（青云诀=修为产出，玄龟诀=护劫减伤）各显示当前效果、下级效果、升级需残页数。
  - 按钮：修青云诀 / 修玄龟诀（切换主修）、升级功法（消耗残页）。
- 验收：从空档出发，不改存档、不调引擎，能选玄龟诀并升到所需重数，配合装备与护劫丹，完成一次成功天劫。

### P0-2 数值可达性
- 补齐 6 件装备掉落来源，保证"逐节点首通"可行：
  - 青铜剑（初始）、粗布衣（野狼首通）、青锋剑（山匪首通）、木牌（妖兽首通）、玄铁甲（阴魂首通）、玉佩（厉鬼首通）。
- 重排幽冥谷敌人（炼气三层/圆满可逐节点首通，含 20%+ 血量余量）：
  - 阴魂：攻 16 防 10 血 90；厉鬼：攻 21 防 13 血 150；鬼王：攻 22 防 14 血 190。
- 用逐节点模拟（自动化测试）验证 2 图 6 节点均可首通。

### P0-3 坏档导入
- `importSave` 全字段校验：建筑等级 0~3、功法等级 0~3、装备 ID 合法、地图结构、库存非负、际遇/镇压关联合法、时间为有限数。
- 导入前把现档备份为 `backup` 记录；校验/迁移成功后再单事务替换，失败不覆盖原档。

### P0-4 双标签页
- `persistSave` 改为修订号 compare-and-swap：同一事务内读取现存 `revision`，若 `新值.revision <= 现存.revision` 判冲突，不写入。
- 冲突时前端丢弃本地改动、重读最新档并提示"另一标签页正在运行"。
- 引擎补齐所有会改状态的动作都 `revision += 1`（含 settle、预置丹药）。

### P0-5 持久化确认 + 渡劫恢复
- 所有 action 改为 `await persistSave` 成功后才提示"成功"；失败/冲突如实提示，不先报成功。
- 重置：`await clearSave` 完成后再回到创建页。
- 渡劫：`startTribulation` 为纯函数原子结算（扣费→五波→结果→`tribulationLog` 战报）一次返回，`persistSave` 单次写入；刷新/关闭重开读到的是"已结算后"的完整状态，天然不重复扣费/用药/晋级；`tribulationLog` 即恢复记录。

## 验收标准（P0 修复后）

1. 全新空档：创建 → 收收益 → 小进阶 → 六节点全部可首通 → 建筑/功法/装备/炼丹 → 渡劫预览与成功筑基 → 导出/导入/刷新恢复。
2. 导入坏档（建筑等级 99、负资源、错装备 ID、版本不符）给出可理解错误，原档不变。
3. 双标签页交替操作不丢失已成功的结果（旧页不覆盖新进度）。
4. 点击后立刻刷新，不出现"已提示成功却丢失、重复扣费、重置后旧档复活"。
5. 引擎测试 + 新增可达性/坏档/修订号测试通过；tsc + next build 通过。
