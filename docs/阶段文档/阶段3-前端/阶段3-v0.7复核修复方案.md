## 逐项说明

### P0-1 地图缺字段
- 背景：为兼容 v1~v5 旧档缺 `map_yunling`，此前把 `validateMaps` 改成「缺地图放行」，但这把「v6 档缺旧地图」也放行了，导致旧地图进度被默认值静默重置；且 `normalizeSave` 对地图是浅合并，缺 `node_ape` 时 `syncYunlingUnlock` 会访问不存在的节点抛异常。
- 方案：`validateMaps(maps, suppression, schemaVersion)` 增加版本参数——
  - `map_qingyun`、`map_nether`（自早期就存在的旧地图）：任何版本缺失即拒绝。
  - `map_yunling`（v0.7 新地图）：`schemaVersion >= 6` 时缺失即拒绝；`< 6` 时允许缺失（迁移补默认）。
  - 每个必需地图的节点必须齐全，且 `unlocked`/`cleared` 为布尔。
- 防御：`syncYunlingUnlock` 先确认首节点存在再写。
- 验收：v6 缺整张旧地图、缺 `map_yunling`、缺首/中/末节点，均 `importSave` 返回 `ok:false` 且不抛异常、不覆盖现档；v1~v5 缺 `map_yunling` 仍能无损迁移。

### P0-2 结丹战报校验
- `validateJindanTrial`：`waves` 必须恰好 `JINDAN_TRIAL_CFG.wavesPct.length`（5）波，每波 `damage`/`hpAfter` 非负；`log` 每项必须为字符串。
- 验收：缺波、超额波、对象日志、空记录等坏 v6 档均拒绝；合法结丹战报导出再导入完整显示。

### P1-1 结丹预览与资源拆分
- 新增 `jindanTrialCost()` 返回 `{cultivation, spirit, spiritStone}`。
- `jindanTrialGateOk` 只查「筑基圆满 + 护丹灵已首通」，不再查资源。
- `previewJindanTrial` 在闸门通过后始终计算五波/减伤/成本，并返回 `canAfford` 与 `shortfall`（各项差额）。
- `startJindanTrial` 仍二次校验资源，不足返回「结丹门槛未足」。
- 修炼页：预览区始终显示五波与成本；资源不足显示「还差 X 修为/灵气/灵石」并禁用挑战按钮。
- 验收：灵石差 1、修为差 1、灵气差 1、未首通四种状态分别验证展示与按钮；资源补齐后无需重开即可看到同一预览。

### P1-2 预计失败确认
- `game-context.tsx` 的 `startJindanTrial` 在确认文案中，当 `previewJindanTrial` 返回 `success === false` 时追加「本次预计失败，仍会消耗资源与预置丹药」。
- 验收：预计失败时点取消不扣费；点确认只在持久化成功后扣一次。

### P2 PRD 状态
- 标题 `（待审阅）` → `（已确认）`；导语「尚未启动开发」→「已开发并复核」；结尾审阅提示改为已确认说明。不改动需求规则。
