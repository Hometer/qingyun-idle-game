# 阶段 3 · v1.1 开发文档

> 后续规划说明：本文件记录 v1.1 已开发的金丹阶段回顾。当前新的[二十境、每境十层目标](../../PRD/PRD-修仙放置游戏-v1.2-二十境.md)另行实施；本文件中的金丹一层入口不代表永远的境界上限。

> 配套：`docs/PRD/PRD-修仙放置游戏-v1.1.md`（金丹篇章目标 + 事实型阶段回顾，R51～R53）。
> 本版只做「人物页金丹篇章入口 + 篇章页三组成果与事实型阶段回顾」；不新增模型调用、不新增持久字段、不做寿元与轮回、不写 AI 传记。

## 1. 目标

- 人物页（`renwu`）新增「金丹篇章」入口：未达金丹一层显示未开启与条件；达到金丹一层显示入口，不弹强制窗口。
- 新增「篇章」页（`pianzhang`）：展示结丹、三处秘境探索、炼制装备三组成果与完成状态；按实际存档生成事实型阶段回顾。
- 全部从现有本地存档字段动态计算，不另存一篇会与存档分叉的文案。

## 2. 数据字段核对（不升 schema）

`SCHEMA_VERSION` 保持 9，无新增持久字段。成果来源：

| 成果/回顾项 | 数据来源 | 判定 |
| --- | --- | --- |
| 结丹 | `realm`、`jindanTrial`、`milestones`(type=`jindan`) | `realm === "jindan1"` 视为已结丹 |
| 三处秘境探索 | `secretRealmLog`(realm/won/at)、`milestones`(type=`realm`) | 某秘境存在 `won===true` 记录即该秘境成功 |
| 炼制装备 | `milestones`(type=`craft`/`forge`)、`inventory`、`equipment` | 存在 `craft` 记录（或 `inventory` 有 `w_steel`/`a_steel`）视为已炼制 |
| 角色资料 | `name`、`spiritRoot`、`aptitude`、`realm` | 直接展示 |
| 地图首通 | `milestones`(type=`firstClear`)、`maps[*][*].cleared` | 归入「历练」回顾 |
| 突破记录 | `milestones`(type=`breakthrough`/`tribulation`/`jindan`)、`breakthroughRecords` | 归入「境界」回顾 |

历史不完整（旧档缺少某类记录）时按 PRD 显示「尚无记录」或「此前记录未收录」，不得从文案猜测补造。

## 3. 引擎能力（纯计算，无副作用）

新增纯函数（`engine.ts` 或独立 `chapter.ts`）：

```ts
export interface ChapterGoal { id: "jindan" | "realm" | "craft"; title: string; done: boolean; detail: string; link?: "xiulian" | "lilian" | "beibao"; }
export interface ChapterReviewItem { group: "境界" | "历练" | "秘境" | "制作"; text: string; time?: number; }
export interface ChapterView {
  atJindan: boolean;            // 是否已达金丹一层
  goals: ChapterGoal[];         // 三组成果
  review: ChapterReviewItem[];  // 事实型阶段回顾（按时间正序或分组）
}
export function computeChapter(state: SaveState): ChapterView;
```

- 纯函数、无副作用、不写 `state`、不发奖励、不重置每日次数、不改旧里程碑。
- 回顾条目只取已持久化事实；`time` 缺失时显示「此前记录未收录」，不虚构时间。

## 4. UI

- **人物页**（`renwu/page.tsx`）：新增「金丹篇章」区块。
  - 未达金丹：显示「尚未开启 · 需金丹一层」。
  - 已达金丹：显示入口链接到 `/pianzhang`。
- **篇章页**（新增 `frontend/src/app/pianzhang/page.tsx`）：
  - 三组成果卡：结丹 / 三处秘境探索 / 炼制装备，各显示完成状态；未完成项给对应页面入口（修炼/历练/背包）。
  - 阶段回顾：按「境界 / 历练 / 秘境 / 制作」分组列事实条目；空缺分组显示「尚无记录」或「此前记录未收录」。
  - 桌面及 360/390/430px、深浅色、减少动效可阅读、可操作。

## 6. 验收（对齐 PRD 第 4 节，逐句抄录）

- 玩家读完知道：已结丹、有哪些真实探索和制作经历、哪些支线仍可继续。
- 每条经历都能从存档找到依据；缺失记录被明确标记。个别措辞平淡可以接受；虚构战果、奖励、关系或把「当前篇章」说成「轮回/寿终」不可接受。
- 自动测试检查事实来源、旧档缺失、重复打开、导出导入后结果和页面状态。
- 未达金丹：人物页显示未开启及条件，不提前显示「已完成金丹篇章」。
- 已达金丹：入口可见、不弹窗；篇章页三组成果从存档事实计算，不能点一下领成完成；旧档升级后正确显示。
- 三组成果是回看线索，不组成通关门槛；未探索/未炼器也能查看回顾。
- 默认确定性模板，不新增 AI 调用、不新增费用。
