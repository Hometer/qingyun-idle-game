# 阶段 3 · v1.0.2 上线安全与部署准备方案

> 依据：`docs/evidence/阶段3-v1.0全局复核/验收复核.md` 中的三项暂缓项（P0-2、P0-3、P1-3）与 v1.0.1 复盘中发现的 iron 校验缺口。
> 性质：在进入阶段 4 前，把「能现在用代码修好」的上线安全与部署项先闭合；需要部署基础设施的项明确留到阶段 4。

## 范围

| 编号 | 问题 | 本轮动作 |
| --- | --- | --- |
| P0-2 | Next.js 15.1.6 有 RCE CVE | **修**：升到 15.x 安全 backport 15.5.26，同步 eslint-config-next，重跑全套 |
| P0-3 | 费用边界（访问码空放行 / 无长度上限 / 无月度熔断 / 单进程限流） | **修前三项**：生产模式访问码强制、请求体长度上限、文件持久化月度费用熔断；**限流共享化留阶段 4**（需 Redis 等共享存储） |
| P1-3 | 代理写死 localhost:8001 | **修**：后端地址改为构建时环境变量注入，本地默认 localhost:8001 |
| — | iron 奖励一致性未比对期望值 | **修**：秘境记录奖励一致性校验补 `iron` |

## 逐项方案

### P0-2 Next.js 升级
- `next` 15.1.6 → `15.5.26`（`backport` tag，官方 15.x 安全修复分支），`eslint-config-next` 同步到 15.5.26。
- 升级后重跑 typecheck / test / lint / build + 浏览器冒烟。

### P0-3 费用边界
1. **访问码强制（生产）**：新增 `ENVIRONMENT` 配置（默认 `development`）。`security.access_allowed` 改为：生产模式下未配置访问码一律拒绝（fail-closed）；开发模式保持原行为（空访问码放行，便于本地）。
2. **请求体长度上限**：`schemas/encounter.py` 给所有字符串字段加 `max_length`，`options` 上限 4、`recent_logs` 上限 20 条且每条 ≤300 字。
3. **月度费用熔断**：新增 `services/budget.py`，按自然月累计估算费用并写入 `backend/data/spend.json`（重启可恢复，符合持久化底线）。每次模型调用前按「提示词长度上界 + max_tokens」估算本次成本，超出 `MONTHLY_BUDGET_RMB`（默认 100）即降级模板、不发起调用；调用成功后按 `usage` 实际 token 数记账。价格用可配置的 `MODEL_INPUT_PRICE_PER_MTOK` / `MODEL_OUTPUT_PRICE_PER_MTOK`（默认按 DeepSeek 标价，产品经理可改）。
4. **共享限流**：留阶段 4（多实例部署需 Redis 等共享存储，本地单实例单进程限流已够用）。

### P1-3 部署地址注入
- `next.config.mjs` 的 rewrite 目标改为读 `process.env.NEXT_PUBLIC_BACKEND_URL ?? "http://localhost:8001"`；构建时注入，本地不设则仍走 localhost。

### iron 一致性
- `validateSecretRealm` 记录奖励一致性循环把 `iron` 加入比对键（与五项基础资源一致）。

## 验收标准
1. `npm audit --omit=dev` 无 critical/high；typecheck / test / lint / build 全过。
2. 后端：生产模式 + 空访问码被 403；超长请求体 422；预算耗尽降级模板且 `spend.json` 可恢复；14 个后端测试 + 新增用例全绿。
3. 前端：本地不设环境变量仍能走 localhost 后端；iron 坏档拒绝。
4. 既有 v1.0.1 修复不回退。
