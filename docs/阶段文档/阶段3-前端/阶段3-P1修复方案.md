## 逐项说明

### P1-6 决策信息
- 洞府：每建筑显示当前效果、下一级效果、升级需灵石；灵石不足时按钮禁用。
- 背包：炼丹显示配方（灵草 X + 灵石 Y，随炼丹炉等级变化）；不足禁用。
- 历练：未解锁节点显示"需 X 境界"；已解锁但境界不足禁用战斗并显示条件。
- 战败：引擎在战报末尾加一行"短板：…，建议…"（攻击不足→换武器；承伤过高→强化护甲/佩饰）。

### P1-7 渡劫展示
- 引擎：新增 `simulateTribulation`（返回 maxHp、减伤、来源列表、逐波 {damage,hpAfter}、丹药恢复、结果、战报），`previewTribulation` 与 `startTribulation` 共用，杜绝两套算法。
- 修炼页渡劫预览：当前气血、减伤来源（功法/装备分别列出 + 合计上限 40%）、逐波伤害与剩余气血、第三波丹药恢复、预计结果。
- 渡劫后：展示 `tribulationLog` 完整战报；失败时给准备建议（升玄龟诀、穿减伤装备、预置护劫丹）。

### P1-8 离线收益
- 资源栏分两行：已入账（持久化值）+ 待领取（每秒累积增量）。
- "领取收益"：结算并提示"本次领取 +X 修为…"。
- 进入页面：提示"离线 X 小时，收获 +Y…（超 12 小时按 12 小时计）"。

### P1-9 AI 超时与访问码
- 前端 `fetch` 超时 5000ms → 4000ms，与后端/文档一致。
- 人物页加"访问码"输入，存入 localStorage，请求时带 `x-access-code` 头；后端设了 `ACCESS_CODE` 时校验通过才调模型。

### P1-10 错误格式
- 后端已用 `HTTPException` 处理器统一为 `{"error":{"code","message"}}`；补 `RequestValidationError`（参数非法）的 pytest 断言，确认两者格式一致。

## 验收标准（P1 修复后）
1. 洞府/背包/历练每个按钮旁都能看到"当前→下级效果、消耗、缺什么"；资源不足按钮置灰。
2. 战败战报末尾有短板与提升路径。
3. 渡劫预览逐波、含减伤来源与丹药恢复；渡劫后能看到完整战报；预览伤害与结算一致。
4. 资源栏有"已入账/待领取"；进入显示离线时长与增量、12 小时封顶提示。
5. 后端设访问码时，前端填码后际遇正常、不填则降级；超时 4 秒内显示模板。
6. 接口错误统一 `{"error":{"code","message"}}`（参数错误与业务错误均如此）。
7. `tsc`、引擎测试、后端 pytest、`next build` 全绿。
