## 二、根因与修复

### P0-1 存档（引擎 `engine.ts`）

**根因**：`validateSecretRealm` 用动态的 `SCHEMA_VERSION` 判「当前档必填」：

```ts
const isCurrent = schemaVersion >= SCHEMA_VERSION;  // 现为 9
```

秘境三字段（`secretRealmUsed/Log/Date`）是 **schema v8** 引入的，必填门槛应写死 `>= 8`。v1.0 把 `SCHEMA_VERSION` 从 8 升到 9 后，v8 档被误判为“旧档”，删掉字段也放行，随后 `normalizeSave` 用默认值把当日次数重置。这是 v0.8、v0.9 已踩过的同类“版本门槛用相对值”坑的复发。

**修复**：
1. 新增字段引入版本常量 `const SECRET_REALM_INTRO_VERSION = 8;`（对齐既有 `MAP_YUNLING_INTRO_VERSION = 6` 写法）。
2. `isCurrent` 改为 `schemaVersion >= SECRET_REALM_INTRO_VERSION`。
3. 补回归测试：`schemaVersion=8` 缺 `secretRealmUsed` 拒绝导入；v8 已领奖档删字段后导入，不得重置当日次数（同日不得双领奖）。

### P1-1 玩法说明（界面 + 配置）

**根因**：
- 秘境奖励预览（`lilian/page.tsx` 的 `rewardParts`）只拼 `cfg.reward` 的灵石/灵草/残页，而玄铁产出在 `CONFIG.iron.realmDrop`，不在 `cfg.reward`，所以预览漏玄铁。
- 旧装备 `a_iron` 与新炼成装备 `a_steel` 在 `config.ts` 里都叫「玄铁甲」，背包/图鉴易混。

**修复**：
1. 导出引擎里的 `secretRealmReward(realmId)`（它已含 `iron`），预览改用它拼奖励行，单一份来源。
2. 旧掉落甲 `a_iron` 改名「玄铁软甲」（防+10，阴魂首通掉落），保留 v1.0 交付物 `a_steel`「玄铁甲」（防+15，炼成）。同步 v1.0 PRD 第 42 行对旧甲的指称。

### P1-2 Lint（工程）

**修复**：加 `eslint` + `eslint-config-next`（版本与 Next 15.1.6 匹配），建 `.eslintrc.json`，`package.json` 加 `lint` 脚本；跑通并清掉报错，闸门 #4 从「否」改「是」需实际运行通过。

## 三、测试与复验计划

1. 前端 `npm test`：新增 v8 缺字段/同日双领奖回归用例，全绿。
2. `npm run typecheck`、`npm run build` 通过。
3. `npm run lint` 首次跑通（新增脚本）。
4. 浏览器复验：秘境卡奖励显示玄铁（灵药谷 +2 / 古修遗迹 +3 / 幽窟险境 +5）；背包/图鉴两件甲名称不重复。

## 四、验收标准

1. v8 档缺 `secretRealmUsed` 拒绝导入且现档不变；同日重复领奖被拦。
2. 秘境奖励预览显示玄铁；两件甲名称区分；PRD 文案同步。
3. 闸门 #4 三项（typecheck / lint / build）全部实际通过。
4. 既有 v0.7～v1.0 修复不回退（前端测试总数 ≥ 现有 132 并增加回归用例）。
