# 第 3 阶段前端开发文档

> 配套：`前端技术适配声明.md`、PRD、阶段 2 引擎（`frontend/src/engine`）。
> 本阶段只做正式前端，不新增游戏规则、不提前做账号/PVP/内购。

## 1. 本阶段目标

用一句产品语言：**玩家能在手机上舒服地完成"创建角色 → 收收益 → 小进阶 → 历练 → 际遇 → 渡劫"一整局首玩。**

## 2. 范围

### 本阶段包含
- 页面：创建角色、洞府、修炼（含渡劫预览）、历练、背包、人物（含存档导入导出/重置）。
- 组件：底部五入口导航、资源栏、境界进度、战斗战报、际遇弹层（AI/模板）、确认对话框。
- 接口：`POST /api/v1/encounter/generate`（际遇文案）。
- 状态：SaveState（IndexedDB）、际遇待选择、渡劫预览/结算、加载/空/失败态。
- 产物：际遇文案展示。

### 本阶段不包含
- 账号、登录、PVP、内购。
- P1/P2 系统（藏经阁、炼器台、灵兽园、辅修、妖气复聚、传记、轮回、NPC 对话）。
- 语音/麦克风等真机能力。

## 3. 用户流程

1. 首次打开 → 创建角色（姓名 + 五行灵根）。
2. 修炼页收收益、小进阶；炼气圆满后看劫势、渡劫。
3. 历练页选地图节点战斗、镇压；战斗后可能触发际遇。
4. 际遇弹层展示 AI 文案（或模板），选选项领奖励。
5. 洞府页升级四建筑、炼丹炉炼护劫丹；背包页穿装备、预置丹药；人物页看属性、导出/导入/重置存档。

## 5. 接口契约

- 接口：`POST /api/v1/encounter/generate`
- 请求：`{ event_id, character:{name,realm,spirit_root}, map_id, options:[{option_id,label,meaning}], recent_logs }`
- 成功返回：`{ source:"model"|"template", event_id, title, body, options:[{option_id,option_text}] }`
- 错误：`{"error":{"code","message"}}`（422/429/403/500，统一结构）
- 超时与重试：前端 4 秒超时（后端同），失败/超时立即用本地模板兜底，玩家始终能继续。
- Mock 与真实切换：后端无 Key 时自动返回模板，前端无需切换。

## 6. 实现方案

- 路由：App Router，`/` 重定向到 `/xiulian`；五入口 `/xiulian` `/lilian` `/dongfu` `/beibao` `/renwu`，底部导航切换。
- 组件结构：`app/layout.tsx`（壳 + 底部导航）、`components/`（ResourceBar、ConfirmDialog、EncounterModal、BottomNav）。
- 状态来源：`lib/game-context.tsx` 用 React Context 持有 SaveState，`useGame()` 暴露 action（settle/breakthrough/fight/…），每次 action 后写 IndexedDB。
- 流式/轮询：无。
- 响应式：Tailwind 移动优先，桌面居中限宽 560px。
- 安全隐私：模型 Key 不在前端；AI 请求只发最少上下文；不记录姓名/完整存档日志。

## 7. 验收标准

- 给定新角色，能完成：小进阶 → 首通并镇压野狼 → 触发际遇看文案选选项 → 渡劫预览（PRD 7.2 场景 1）。
- 375px 与 1280px 宽度均可用（PRD 场景 1 窄屏可操作）。
- 刷新页面：收益不重复、际遇/渡劫状态不丢、不双扣。
- 际遇：后端停掉或超时仍显示模板，可选奖励。
- 自动检查：`npx tsc --noEmit`、`npm test`（引擎）、`npm run build` 通过。
- 真实联调：际遇走真实后端（已有 Key）。

## 8. 风险与回退

- 风险：Next.js 迁入后引擎/测试与构建不兼容。
- 降级方案：引擎为纯 TS，若有框架耦合问题，退化为"Next.js 壳 + 静态导入引擎"，不影响游戏逻辑。
- 回退方式：git 已提交阶段 2 版本，可随时回退。
