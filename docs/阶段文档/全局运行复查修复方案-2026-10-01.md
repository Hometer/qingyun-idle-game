# 全局运行复查修复方案（R1～R5）

> 依据 `docs/阶段文档/全局运行复查-2026-10-01/复查报告.md`（基线 `4928a9c`）。先关 R1/R3 存档保护与 R2 费用保护，再处理 R4/R5。

## R1（P1）空词条装备导回失败

- `validateAffixList` 允许 0 条词条（旧装备/初始装备迁移后为 `affixes=[]`，属合法），仅保留上限 ≤4 与结构校验。
- 复验：新建→刷新→导出→导入→再导出→再导入；v13 旧装备迁移后同样两轮通过；不随机补词条。

## R2（P1）预算账本异常与并发突破

- `budget.py`：坏/错形状账本**失败关闭**（`_load` 抛异常，`current_spend_rmb` 返回 `inf`，`budget_exceeded` 因此返回 True → 降级模板，不再放行）。
- 原子预留：新增 `reserve(cost)`（锁内检查+累加 `_pending`）与 `settle(reserved, usage)`（锁内释放预留并按实际 usage 记账）；`llm.py` 调用前 `reserve`，成功后按 usage 结算、失败释放。
- 复验：坏 JSON/数组/非法月值均降级模板；并发两线程只放行一个；成功/失败/异常均释放预留。

## R3（P1）读档失败与坏档启动恢复

- `game-context` 加载流程区分「空档 / 读失败 / 坏档」：
  - `loadSave()` 抛错 → 显示「读取失败」+ 重试按钮，不冒充空档进建角。
  - 加载后先用 `eng.validateSaveObject(saved)` 校验；不合法 → 提示「存档损坏」并提供「导出原档 / 恢复导入前备份」，不进入 `migrate/ settle`，避免客户端崩溃。
- 引擎新增 `validateSaveObject(raw)`（复用 `importSave` 的校验，不归一化），供加载路径调用。
- 复验：注入 `indexedDB.open` 读取异常显示读取失败并可重试；删除 `daily.goals` 的坏档启动进入恢复提示，不崩溃；恢复入口不依赖游戏页面正常渲染。

## R4（P2）委托候选补资源可完成校验

- `commissionCompletable` 战斗候选加「当前可胜」判定（`predictFight(...challenge).won`）；制作候选加「材料/灵石足够」判定；候选生成、接取、预览共用同一条件。
- 复验：零灵石炼气一层不生成/不接取「升级修炼室」；有足够资源时正常生成并接取。

## R5（P2）端到端超时一致

- 前端 `api.ts` 超时与后端总预算协调：后端把「业务重试 × 单次超时」压进一个总预算（如单次 3.5s、最多 2 次），前端 4s 取消前不继续触发新请求；后端超时后立即降级模板，不在前端已放弃后继续消耗费用。
- 复验：晚返回不改变已采用模板结果；超时不产生额外真实扣费（用假 SDK 计时验证）。

## 复验
每项：保留现有测试 + 补回归；前端 `npm test`/typecheck/lint/build；后端 `pytest`；浏览器独立来源走新建→导出→导入→刷新→重启，资源只结算一次。
