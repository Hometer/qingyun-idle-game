## 1. 项目判断

- 产品类型：移动端优先的单机网页文字放置游戏（修仙题材）。
- 主要用户：喜欢修仙题材、文字氛围和渐进成长的放置玩家。
- 主要终端：**移动 Web 优先**，兼顾桌面 Web（本手册 2.2 的"游戏"主要指 3D/实时协作类，本项目是文字 + 点击，属常规 Web 应用）。
- 新项目或已有项目：已有项目（阶段 2 已有 Vite 临时验收页 + 纯 TS 引擎）。
- 本阶段业务目标：把五个主入口（洞府/修炼/历练/背包/人物）做成正式移动端界面，复用阶段 2 引擎，跑通完整首玩闭环。

## 3. 技术选择

| 项 | 选择 | 说明 |
| --- | --- | --- |
| 框架 | Next.js 15 App Router + TypeScript strict | 手册默认；从 Vite 迁入，引擎纯 TS 复用 |
| 样式 | Tailwind CSS + 语义化设计变量 | 中性修仙风：宣纸米色底 + 墨色字 + 朱砂点缀 |
| 数据与状态 | 游戏状态在浏览器本地（IndexedDB），React Context + 自定义 hook 承载 SaveState | 单机本地存档（PRD 6.1） |
| API 请求 | 集中式 API 层（`lib/api.ts`） | 只用于际遇文案，4 秒超时降级模板 |
| 流式通信 | 无 | 文案一次性返回 |
| 表单 | 受控组件 + 客户端校验 | 创建角色（姓名/灵根） |
| 测试 | Vitest（引擎单测沿用）+ tsc + next build + 浏览器人工检查 | |
| 部署环境 | 本地预览（阶段 4 再定） | |

## 4. Agent 状态

- 本产品 AI 只写际遇文案，4 秒超时、失败降级模板，**无长任务、无流式、无任务队列**，手册第 9/10/11 节的"任务状态模型/流式/取消重试"不适用。
- 际遇"待选择"由引擎 `encounter.pending` 字段承载，刷新/重进经 IndexedDB 恢复，无需服务端任务 ID。

## 5. 页面与产物

- 核心页面：创建角色页 + 五个主入口（洞府、修炼、历练、背包、人物）+ 渡劫预览/结算 + 际遇弹层。
- 核心业务闭环：创建角色 → 收取收益 → 小进阶 → 历练战斗/镇压 → 际遇（AI 或模板）→ 渡劫筑基。
- 产物类型：际遇文案（半文半白短文本）。
- 响应式目标：375px 移动优先，桌面居中限宽（≤560px）。

## 6. 偏离本手册的地方

| 偏离项 | 原因 | 影响 |
| --- | --- | --- |
| 手册默认面向"AI Agent 长任务产品" | 本项目是游戏 + 局部 AI 文案 | 流式/任务中心/断线恢复等章节不适用，界面以游戏状态而非任务状态为主 |
| 重客户端应用 | 引擎与存档在浏览器本地 | 多数页面为 `use client`，Next.js 主要作为壳与路由 |
