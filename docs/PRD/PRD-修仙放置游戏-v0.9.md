# 「青云修仙录」产品需求文档 v0.9（待审阅）

> 起草日期：2026-09-25。依据[已确认的后续版本路线图](../阶段文档/规划/后续版本路线图-v0.6之后.md)起草，聚焦“回访历练不再重复”。本文是需求草案，尚未确认具体内容量与数值，未启动开发。未被本文明确改写的 v0.2～v0.8 规则继续有效。

## 1. 版本目标与边界

v0.8 让玩家在功法主辅间形成修行取向；但历练页的三张地图一旦首通，回访就只是重复刷同一批节点，没有可期待的变化。v0.9 要新增一组**可主动进入的秘境**，各有不同风险与奖励主题，让玩家在常规历练之外多一个“去碰碰运气”的选择。秘境是确定性结算（沿用现有回合战斗），不引入概率掉落；AI 只写进入叙事，不决定胜负或奖励。

本版建议交付：**三个秘境（灵药谷 / 古修遗迹 / 幽窟险境），按境界开放，每日各限一次**。秘境不替代旧地图、镇压、长期任务或每日目标；已首通的旧节点照常可刷，秘境只是新增的可选变化。不新增概率战斗、随机词条、付费资源或在线系统。

真实玩家试玩与物理真机操作按产品经理既定决定留到最终总体验收。本版开发仍须完成程序模拟、自动测试、浏览器宽度检查、旧档迁移与证据包；未经真人试玩，不宣称平衡或手感已验证。

## 2. 玩家主流程

1. 角色达到对应境界后，历练页「秘境」区块显示三个秘境入口及其境界门槛、敌方强度、奖励主题与今日剩余次数。未达境界的秘境显示解锁条件，不能进入。
2. 玩家选择进入某个秘境，先看到一段进入叙事（环境描写与本次目标），再发起一次确定性战斗。战前显示敌我属性与胜负预估；胜则按该秘境主题发放奖励，败则无奖励、可明日再试。
3. 每秘境每日限挑战一次；三个秘境互不影响，各自按日重置。重置沿用现有“跨日刷新”规则，不额外消耗资源。
4. 探索结果写入修仙录/图鉴：胜败、秘境名、当次奖励、时间。旧档无秘境历史时不补写虚构记录。
5. 刷新、关闭重开、导出导入或双标签竞争后，当日的次数消耗与探索结果保持一致，不能重复领奖或重复挑战。

## 3. 首轮规则基线

以下数值是供开发模拟的**建议基线**，不是最终平衡结论。配置、前端预览、结算和测试须共用同一来源。开发前用 v0.7 可获得的装备、三种资质与典型功法配置模拟三个秘境的胜负；若某秘境对所有典型装配都稳胜或都稳败，应调整强度并在开发文档说明。

### R46 秘境与开放

| 秘境 | 开放境界 | 敌方攻/防/气血 | 胜利奖励 | 说明 |
| --- | --- | --- | --- | --- |
| 灵药谷 | 筑基一层 | 25/16/200 | 灵草 30、灵石 100 | 低风险，灵草与灵石 |
| 古修遗迹 | 筑基二层 | 28/18/240 | 残页 8、灵石 200 | 中风险，残页与灵石 |
| 幽窟险境 | 筑基圆满 | 32/21/300 | 灵石 500、灵草 50 | 高风险，灵石多 |

- 秘境是**主动进入的确定性战斗**，复用现有回合战斗与胜负预估；敌人属性固定，不掷隐藏命中/暴击。奖励只发一次，战败不发，不设保底。
- 每秘境每日一次，跨日重置；三个秘境共用“探索次数”不设额外上限，但每日总计最多三次。秘境战斗不计入“完成 3 次战斗”每日目标、不触发天气/星象限次、镇压或长期任务奖励。
- 秘境不产出新货币、新装备；奖励只用现有 灵草/灵石/残页。旧地图镇压仍是灵石来源，旧重复战斗仍是残页来源，秘境只是补充路径，不取代旧来源。
- 境界不达不可挑战；挑战按钮在战力不足时仍可按玩家意愿进入（明确显示“预计难胜”与失败无奖励）。

### R47 AI 叙事与结算边界

- 三个秘境各有一段**进入叙事**（环境描写），复用现有 AI 际遇文案管线与模板降级；AI 只写叙事文字，不决定胜负、掉落或奖励。AI 请求仍只发最少上下文（道号/境界/地图/秘境名/最近两条摘要），不发送完整存档或功法配置。
- 结算由引擎确定性完成：胜负用现有回合公式，奖励用秘境配置，两者与预览一致。AI 叙事只在进入时展示一次，不参与重试判定；刷新后重进同一秘境不再重复调用 AI，直接用已保存的结果或当日状态。
- 成本边界：每秘境每日一次、总计最多三次，不新增模型机制，只可能略微增加当日 AI 调用次数，仍受现有访问码/限流/超时与模板降级约束。月度成本上限沿用已定决策，不在本版调整。

### R48 记录与回看

- 修仙录记录每次秘境探索：`秘境「名」成功/失败，得 …`；图鉴记录每个秘境首次探索与首次成功。旧档不补造历史。
- 当日次数状态随存档持久化；导出/导入保留秘境探索记录与当日次数。坏档（非法秘境状态、负次数、非法奖励）拒绝导入并保留现档。

## 4. 页面与反馈

- 历练页「秘境」区块：三张秘境卡展示境界门槛、敌方属性、奖励主题、今日剩余次数与胜负预估；按钮进入前有确认。进入后展示叙事与战报；胜利/失败回执清晰。
- 人物页/修仙录与图鉴可回看秘境探索记录。桌面与 360/390/430px、深浅色与减少动效下可读可点。

## 5. 存档、并发与安全

- 存档 schema 预计 v7→v8，新增秘境探索记录与当日次数状态。v1～v7 旧档升级：秘境记录为空、当日次数为 0，其余保留。升级前有可恢复备份。
- 进入秘境、结算与奖励、次数扣减在同一次持久化提交；失败不显示成功回执。双标签沿用代次与修订号保护，同一秘境同日只允许一方提交成功。
- 不新增账号、在线交易、多人或云资源；不把完整存档或功法配置发给模型。

## 6. 验收场景

| 场景 | 必须看到 |
| --- | --- |
| 开放与门槛 | 未达境界的秘境显示条件不可进；达境界可进；每日一次，跨日重置。 |
| 确定性结算 | 战前预估与实战一致；胜得对应奖励、败无奖励；不重复领取。 |
| AI 叙事 | 进入时展示叙事，模板降级可用；AI 不决定胜负与掉落；刷新不重复调用。 |
| 记录与回看 | 修仙录/图鉴可回看探索记录与首次成功；旧档不补造历史。 |
| 存档与并发 | v1～v7 旧档无损升级；坏档拒绝且现档不变；双标签同秘境同日只成功一次。 |
| 不破坏旧内容 | 旧地图、镇压、长期任务、每日目标、天气/星象照常；秘境战斗不计入每日战斗目标。 |
| 界面 | 桌面与 360/390/430px、深浅色、减少动效可操作。 |

开发交付按 `AGENTS.md` 提供阶段开发文档、自动测试、类型检查、生产构建、浏览器关键闭环、旧档/坏档/并发验证、截图与阶段闸门是否表。真实玩家试玩与物理真机操作届时如未进行，仍如实记“待验”。

## 7. 本版不做与待确认

- 不做 v1.0 的炼器/新装备位/随机词条，不做宗门、灵兽、道侣、寿元轮回或账号；秘境不扩成抽卡、无尽塔或门派科技树。
- **待产品经理确认的范围选择**：是否按本稿“三个秘境（灵药谷/古修遗迹/幽窟险境）+ 每日各一次 + AI 进入叙事 + R46 首轮强度/奖励基线”推进。路线图只确认了“探索变化”方向，具体秘境数量、强度、奖励与 AI 叙事属于本稿推荐方案；确认前不生成 v0.9 阶段开发文档，也不启动开发。
