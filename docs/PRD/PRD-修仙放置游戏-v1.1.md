# 「青云修仙录」产品需求文档 v1.1（待确认稿）

> 起草日期：2026-09-26。依据[已确认路线图](../阶段文档/规划/后续版本路线图-v0.6之后.md)与[竞品参考](../阶段文档/规划/v1.1竞品参考与范围建议.md)起草。本文是建议范围，尚未获得产品经理确认，未启动 v1.1 功能开发。未明确改写的 v0.2～v1.0 规则继续有效。

## 1. 目标用户与核心任务

面向已走到金丹一层、仍想回看这位角色成长经历的放置修仙玩家。当前境界到顶后，玩家应知道这段修行已经取得什么、还可补完哪些已有内容，并能读到一份忠于实际存档的阶段回顾。

**版本目标：金丹篇章目标 + 事实型阶段回顾。** 本版称“当前篇章”，不称“一生结局”；玩家查看或完成篇章目标后仍可继续修炼、探索和炼器。

## 2. 输入、过程和产物

- 输入：现有本地存档中的角色名、灵根/资质、境界、地图首通、秘境成功记录、炼器记录与修仙录里程碑。玩家无需额外输入。
- 过程：人物页展示“金丹篇章”入口。达到金丹一层后，列出三组成果与完成状态：结丹、三处秘境探索、炼制装备。未完成项给出对应现有页面入口；炼器是可选支线，不影响结丹成绩。
- 产物：可随时重看的阶段回顾，按实际发生的关键事件归类，显示时间或“此前记录未收录”。不为缺失的旧档历史补造事件。
- 数据保留：沿用本地存档及其导出/导入；优先从现有事实字段动态生成回顾，不另存一篇可能与存档不一致的文案。开发前核对字段是否充分。

## 3. 主链路与交互规则

### R51 金丹篇章入口

1. 未达到金丹一层时，人物页可显示尚未开启及明确条件；不提前展示已经“完成金丹篇章”的文案。
2. 首次达到金丹一层时，人物页入口可见，不弹强制中断流程的窗口。
3. 篇章页显示结丹、秘境、炼器三组成果。每组状态从已持久化的存档事实计算，不能由前端一次性点击领取变成完成；已达成的旧档升级后也应正确显示。
4. 三组成果是回看线索，不组成通关门槛。未探索秘境或未炼器的玩家也能查看阶段回顾，不因此失去既有玩法。

### R52 事实型阶段回顾

1. 回顾只可包含可核对的角色资料与已发生事件。以结丹为主线，归纳已记录的地图首通、秘境成功和装备炼制；空缺分类显示“尚无记录”或“此前记录未收录”。
2. 每一条关键经历可回到修仙录中的原始记录或对应图鉴/进度查看；若现有字段只能证明“曾经拥有”而不能证明“何时完成”，不得虚构时间。
3. 回顾随着真实进度更新；重复打开不增加奖励、不重置每日次数、不改写旧里程碑。
4. 默认用确定性模板生成，不引入 AI 传记或新模型调用。文案不得给玩家捏造师门、道侣、战果、选择或奖励。

### R53 兼容与反馈

1. 沿用本轮已补的修仙录逐条导入校验：`milestones` 每条记录的类型、时间和文本必须有效，畸形档拒绝导入且不覆盖原档。旧档可直接查看已知事实；历史不完整要如实标识，不能为了凑篇章要求用户新开一局。
2. 如果开发发现必须新增持久字段，先在阶段开发文档写清 schema 迁移、坏档拒绝、可恢复备份与双标签页并发处理，再编码；没有必要时保持现有存档结构。
3. 页面在桌面及 360/390/430px 宽度、深浅色与减少动效设置下可阅读、可操作。

## 4. 什么算结果好

- 玩家读完知道：已结丹、有哪些真实探索和制作经历、哪些支线仍可继续。
- 每条经历都能从存档找到依据；缺失记录被明确标记。个别措辞平淡可以接受，虚构战果、奖励、关系或把“当前篇章”说成“轮回/寿终”不可接受。
- 本地自动测试检查事实来源、旧档缺失、重复打开、导出导入后结果和页面状态；最终让真实玩家判断“这段回顾是否像自己的角色”，样本与评分留到总体验收，不先宣称通过。

## 5. 交付阶段与优先级

v1.1 只交付 R51～R53。未来的师承、灵兽、道侣、宗门、AI 长篇传记、寿元和轮回分别立需求。已有的修仙录和图鉴仍保留，不以篇章页替换。

开发顺序建议：先做现有存档字段核对与缺失情况表，再做确定性篇章计算及旧档兼容，最后做人物页展示与浏览器检查。自动测试、类型检查、Lint、生产构建、存档与并发复核通过后提交证据包。

## 6. 模型与成本约束

本版不新增模型调用、不改变现有 DeepSeek 际遇/秘境叙事链路，也不新增云资源或费用。当前月度费用暂按现有 D4/D9 边界；AI 传记需另立 PRD 和真实样例验收。

## 7. 数据与非功能要求

回顾只从玩家自己的浏览器本地存档生成；不把完整修仙录发给模型或写进后端日志。导入畸形数据不能造成页面崩溃、覆盖现档或编出经历。正式上线前仍需处理共享限流与依赖安全项；本版开发不等同对外上线。

## 8. 上线、账号与验收节奏

沿用匿名访问、邀请码和本地存档。产品经理决定把真实玩家试玩、物理真机、正式部署及新的真实模型验证集中留到最终总体验收；本版可以先做本地开发与自动/浏览器验证，但这些后置项目在阶段闸门中必须写“待验”，不提前宣称最终上线可用。
