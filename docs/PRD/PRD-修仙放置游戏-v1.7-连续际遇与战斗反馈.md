# 青云修仙录 v1.7：连续际遇与战斗反馈

状态：产品经理已于2026-10-01确认完整范围，见项目状态D10；代码已实现，阶段3整体仍未验收通过。末节范围决策卡保留为历史依据，无需重复确认。

参考：《太玄问道》的持续人物与事件反馈、回合战斗呈现；沿用青云修仙录已经确认的放置养成、确定性奖励和本地存档方向。不复制其桌面双模式或自由输入剧情。

## 1. 目标用户与要解决的问题

目标用户不变：喜欢修仙题材、文字氛围和渐进成长，每天登录一至两次的放置玩家。

现有际遇大多在一次选择后结束，玩家难以感到“上次的决定影响了后来”；历练战报虽列出逐次攻防，却不易看出功法、装备词条、暴击或失败原因究竟如何影响结果。v1.7 要让短时登录更有故事连续性，也让玩家更容易判断下一步该升级什么。

本版成功体验：玩家能在后续登录中认出自己曾做的选择；打一场战斗后，能从结果页说出胜负关键及实际获得的奖励。

## 2. 版本范围与交付顺序

| 子阶段 | 本版必须交付 | 不改变什么 |
| --- | --- | --- |
| A 连续际遇 | 现有“古井奇遇”“灵兽现踪”“残破洞府”各增加一个后续事件；选择记入本地存档和修仙录；模型失败时有完整模板 | 原始事件的选项和即时奖励、每日际遇上限 |
| B 战斗反馈 | 历练普通与挑战、守关 BOSS、秘境的战后摘要和可展开逐回合记录；最近一战刷新后可查看 | 伤害公式、敌人强度、掉落、每日奖励上限、挑战回合限制 |

A、B 分别走一次可玩的完整闭环和验收，不等待两者全部完成才展示给产品经理。v1.6 的独立复验及现有阶段 3 待办仍按《项目状态》执行，本 PRD 不把它们视为已关闭。

## 3. 玩家流程与详细规则

### 3.1 连续际遇

1. 玩家照常在历练胜利后遇到“古井奇遇”“灵兽现踪”或“残破洞府”，选择原有选项，立刻领取原有奖励。首次完成其中一条事件时，系统记下事件和玩家选择；同一存档同一条故事只开头一次。当前已有的古井新手引导继续正常触发。
2. 到下一个自然日及以后，玩家再完成任意一次历练胜利，系统优先安排这一条故事的后续。若当天三次际遇额度已满，后续保留到下一次符合条件的胜利；不会过期，也不会挡住玩家战斗和领取奖励。
3. 每次只挂起一条连续际遇。等待期间出现其他同类初始事件，仍按原有单次际遇处理，不同时开启第二条故事；已经完成的初始事件以后也可照常作为单次际遇出现，但不会重复开启故事或发后续奖励。
4. 后续事件依据玩家当初的选项展示不同的开场与结果。玩家在后续事件中再作一次选择，两种结果都只改变故事记录，不新增资源、功法、装备、境界或战斗加成。完成后在修仙录留下“起因—选择—回响”的可读记录。
5. 后续事件占用触发当日的一个际遇名额，替代该次普通随机际遇，不增加每日上限。一次后续事件至多发起一次正常的文案生成流程；由于后续事件会优先触发，实际平均调用次数可能比现在略高，仍须受月度费用熔断约束。已有待处理际遇优先让玩家处理；关闭页面、断网、模型超时或刷新后，未完成的选择仍可恢复，不得自动代选或重复结算。

首批故事只围绕上述三条已有事件写作，不要求新增地图、NPC 属性或专用页面。分支方向如下；具体文案在开发时提交给产品经理看代表样例，必须承认玩家原选择。

| 原事件 | 原选择不同，后续应体现的差别 |
| --- | --- |
| 古井奇遇 | 下井者认出残文的后续线索；绕行者从旁人口中听到井的旧事，不写成亲眼看过井底。 |
| 灵兽现踪 | 救鹿者得到灵鹿再次靠近的回应；静观者在远处重见灵鹿，不写成曾施救。 |
| 残破洞府 | 入洞者辨认曾见札记；记下位置者重访洞外，不写成已拿到札记。 |

### 3.2 AI 与模板边界

- 事件 ID、可选项 ID、分支条件、奖励和完成状态由确定性规则决定。AI 只生成标题、正文和选项文案，不得增删选项、暗示不存在的奖励，亦不得决定故事触发或改写玩家历史选择。
- 后端只接收生成这段文案所需的事件 ID、分支标记、角色最低限度信息和有限近期记录；不发送完整存档。沿用既有结构校验、内容审核、超时、有限重试及模板降级。
- 三条后续事件的所有选择分支都有本地模板。无 Key、超预算、断网、模型失败或返回违规内容时，玩家仍能看到正确分支并完成事件。费用继续受既有月度上限约束，不引入玩家自填 Key。

### 3.3 战斗反馈

1. 战前仍显示现有敌我数值、难度、可得奖励和守关回合要求。凡含随机暴击等因素的胜负提示须标明是预测，不承诺与实际结果完全一致。
2. 战后先显示一屏能读懂的摘要：胜/负、对手与难度、实际回合数、双方剩余气血、是否达到回合限制、实际获得的资源与装备、下一步建议。每日重复奖励已领完时明确写“本次无重复奖励”，不得沿用战前的可得奖励冒充实得。
3. 摘要只强调本场**确实发生**的关键事件，如暴击、每回合回血、低血增伤、装备减伤、功法或星象加成及导致落败的主要原因。未触发的效果不能写成已生效；没有关键事件时只展示普通攻防与结果。
4. 逐回合记录可以展开查看，按回合显示行动、伤害/回复、剩余气血，长战报默认折叠。手机单列阅读，电脑可在现有战报区展示；文字和颜色同时标识胜负及关键事件。
5. 最近一场战斗的结果和精简战报写入本地存档，刷新或重启前端后可在历练页查看；新战斗成功结算后替换，不无限累积。战斗奖励和日额度仍只在实际战斗结算时发放一次，查看战报绝不再次结算。
6. 历练普通/挑战、守关 BOSS 和八处秘境沿用各自现有规则。战报和奖励回执必须对应真实结算；本版不调整战斗胜率或六至八周目标节奏。

## 4. 数据、兼容与异常处理

- 在现有 IndexedDB 存档中保存连续际遇的当前故事、原选择、待触发/待选择/已完成状态和必要时间信息，以及最近一战的有界战报。前端服务重启后数据可恢复；后端仍不保存玩家进度。
- 如新增存档字段，存档 schema 从 v16 升至 v17。v16 及更早合法存档迁移为“尚无连续故事、尚无最近战报”，原有境界、资源、装备词条、地图首通、每日额度和修仙录均保留。
- 导入时检查事件 ID、选项 ID、状态组合、时间和战报长度；无效新字段拒绝导入，当前存档不变。沿用双标签修订号与代次保护，确保同一选择和同一战斗不能重复领奖。
- 待处理际遇与待处理后续事件不会同时覆盖彼此。存档中已有待选事件时，先完成它，再安排后续；自然日切换不清掉故事进度。
- 模型文案失败只降级文案；本地存档写入失败必须提示且不宣称选择或战斗已保存。

## 5. 模型、成本、隐私与上线边界

沿用当前国产模型、后端持有 Key、月度费用上限暂记 100 元的决定。后续事件替代普通际遇且遵守每日三次上限；因其优先触发，月均调用量可能小幅上升，达到现有费用上限时必须降级模板。正式上线、登录和云费用范围不因 v1.7 改变；仍属于尚待阶段 4 确认的工作。

## 6. 本版明确不做

- 自由输入行动后让 AI 决定世界状态、奖励或战斗；AI NPC 自由聊天。
- 手动逐回合战斗、第二套游戏模式、桌面客户端、多角色存档位。
- 新宗门系统、三级自由地图、银市交易、独立 NPC 好感系统。
- 因新增故事而提高每日资源产出、重复奖励次数或模型费用上限。

常驻 NPC、地图场景细节和宗门路线保留为后续候选，须等 v1.7 玩家的反馈与长线平衡结果再单独立项。

## 7. 验收标准

### A 连续际遇

- 三条故事各有两种原选择对应的后续文案，每条后续再有两种纯叙事结尾；共十二条结果路径可走通并留下正确记录。古井引导在新档仍可触发。
- “当天不能出现后续、次日一次历练胜利后优先出现、当日额度满则顺延、已有待选际遇先处理”均按规则执行；后续只占一次额度，不重复发奖。
- 模型与模板两种路径都能完成；模型输出不改变事件 ID、选项或奖励，异常时使用对应分支模板。
- 刷新、前端重启、旧档迁移、导出导入、双标签同时操作后，故事状态与资源不丢失、不复制。

### B 战斗反馈

- 历练普通、挑战、守关 BOSS、秘境各取至少一场胜利和一场失败核对摘要、逐回合记录与实际奖励；12 回合挑战失败和当日奖励用尽要单独覆盖。
- 暴击、回血、减伤、低血增伤分别用可控测试场景核对“真实触发才显示”；战报不靠猜测日志文字得到效果。
- 最近一战刷新和前端重启后可查看，下一战替换；查看、展开或返回页面不重复结算。
- 390px 手机及桌面宽度可读，键盘可展开战报；测试、类型检查、Lint、生产构建与真实浏览器闭环通过。真实模型冒烟、存档重启恢复、密钥排除和阶段证据包按《AGENTS.md》闸门记录，未验证项不得写成通过。

## 8. 范围决定记录（已确认）

**问题**：v1.7 是否按本草案只做“连续际遇＋战斗反馈”？

**选项**：A 按本草案；B 把常驻 NPC、地图场景或宗门路线也并入 v1.7。

**推荐**：A。先完成当前阶段待验项，再分 A、B 两个可验收子阶段实施；其他内容根据真人试玩结果另开版本。

**不选的后果**：选 B 会同时增加剧情内容、界面与平衡验证范围，推迟当前阶段收尾和真人长线体验。
