# 「青云修仙录」产品需求文档 v0.5

> 状态：已确认开发（2026-09-24）。依据[参考站体验对照与版本建议](../阶段文档/参考站体验对照与v0.3候选清单.md)中 v0.5 的“持续历练、多档风险、临时增益、闭关倒计时”方向起草。本文只定义增量；[v0.2](PRD-修仙放置游戏-v0.2.md)、[v0.3](PRD-修仙放置游戏-v0.3.md)、[v0.4](PRD-修仙放置游戏-v0.4.md)已确认且未被本文改写的规则继续有效。

## 1. 版本定位

### 1.1 要解决的问题

当前历练是即时战斗，玩家离开页面后只有修行与镇压收益继续累积。v0.5 增加一个**可离开、可刷新、可回来领取结果**的持续任务：玩家在已有内容中安排一段 30 分钟至 2 小时的历练或闭关，提前看清时间、难度、成本与收益，到期后由本地存档恢复并结算。它提供短时上线的计划选择，不要求玩家一直停在页面。

本版以长任务状态的正确性和可恢复性为第一目标。历练仍用现有地图与已通关节点；闭关仍处在炼气至筑基的既有闭环内。奖励数值是首轮试玩基线，集中配置，不视为最终平衡值。

### 1.2 启动前条件与边界

1. v0.4 的复核修复已有提交；启动 v0.5 开发前，应把修复后的浏览器复验、旧档导入和阶段闸门记录补齐。v0.5 文档可先审阅，不以撰写 PRD 代替验收。
2. 先观察现有玩家是否需要“离开时安排下一步”，特别是首次筑基耗时、回访频率、已有修为/灵气/残页的余量；没有试玩数据时只使用本文可调基线，不声称收益已平衡。
3. 本版不新增境界、地图、敌人、装备位、随机词条、稀有货币、账号、推送、付费或模型调用。即时战斗、镇压、每日目标、天气/星象、离线结算与 AI 际遇按原规则运行；持续任务**不代替**已有即时战斗。

## 2. 玩家主流程

1. 角色已完成首个节点镇压后，“历练”出现“安排持续历练”，“修炼”出现“安排闭关”。未解锁时说明条件。两类活动**共用一个长期任务位**，一次只能进行一项。
2. 玩家选活动、30/60/120 分钟、目标节点或难度档，并看当前装备快照下的结果预估、具体奖励、是否使用一次性的护行阵。确认后才扣可选成本并保存开始与结束时间。
3. 离开页面、切换入口、刷新或关闭浏览器，任务继续按存档中的时间推进。页面倒计时只是展示；到期与结算由确定性引擎根据时间戳判断，不靠活着的定时器。
4. 到期后状态变为“可领取”。玩家打开结果页，看到实际结果并主动领取；奖励、任务完成记录与清空任务位在同一次持久化提交中完成。晚回来不会多领或把下一段任务自动启动。
5. 玩家可主动中止未完成的任务。中止前明确提示本次活动奖励和已支付的护行阵费用不返还；已积累的普通修行与镇压收益仍按原规则结算。

## 3. 共同规则

### 3.1 时间、状态与操作

**R21 单任务状态机。** 每个存档最多一个长期任务，状态至少可区分“无任务、进行中、到期可领取、结果已领取/已中止”。开始、领取和中止均由玩家主动触发；页面关闭不等于中止。任务 ID、类型、开始/结束时间、所选参数、一次性成本、规则版本及结算快照持久化。到期状态可由绝对时间推导，但结果领取状态必须持久化。已有任务未领取时，不能再开第二项。

**R22 三档时长。** 两类活动均可选 30、60、120 分钟。显示开始时间、预计结束时间、剩余时间和“到期后需手动领取”；剩余时间不得为负。`now < endAt` 不可领取，`now >= endAt` 可领取。关闭超过结束时间才回来，结果只结算一次；等待超时不增加任务奖励。

**R23 与现有玩法并行。** 长任务进行时，原有挂机修炼、镇压、每日目标、即时战斗、换装、建筑、功法和渡劫仍可使用。长任务在开始时锁定自己的属性与奖励快照，期间改装备、功法、境界或镇压目标不追改已启动任务。持续历练不计入 v0.4 的“完成即时战斗”每日目标，不触发首胜解锁、镇压、AI 际遇或天气/星象限次奖励。闭关奖励也不触发“领取一次收益”类行为。

**R24 普通离线收益。** 长任务奖励独立于正常修为、灵气、灵田和镇压收益；原有单次最多 12 小时离线结算上限仍只约束这些普通收益。任务最长 2 小时：即使玩家 14 小时后回来，也先依原规则结算普通收益最多 12 小时，再处理已到期的那**一个**任务。天气跨日和镇压复聚仍由 v0.4 的分段规则结算，不把任务奖励混入普通“待领取”数字。

### 3.2 持续历练

**R25 目标与难度。** 只能选择现有地图中**已首通且当前境界仍满足要求**的节点；不能用持续历练开新图或刷首胜装备。每个节点有“稳行”“险行”两档，均沿用确定性战斗引擎：稳行使用原敌方攻、防、气血；险行将敌方三项属性各乘 1.25 并向上取整。按钮前展示原敌人与难度后敌人的属性、当前快照下“预计可胜/预计难胜”及依据。预计难胜的档位本版不可开始，并说明要提升的属性；本版“风险”指敌人难度，**没有隐藏随机胜率**。

**R26 可选临时增益。** 历练可额外选择一次性“护行阵”：开始时消耗灵石 30，**只给本次持续历练的快照防御 +5**。不产生永久道具，不叠加，不影响即时战斗、人物常驻属性或渡劫。开启前同步更新胜负预估、成本与结果；灵石不足时不能选并显示缺口。开始存档失败不扣费；开始成功后主动中止不返还费用。闭关不能选护行阵。

**R27 历练奖励。** 完成时按开始时锁定的节点重复战斗奖励计算，只包括原有重复奖励中的修为和残页，不发首胜、装备、镇压收益或际遇。基线倍率如下，所有资源用同一配置与取整规则，结果可复算；险行倍率只在预计可胜并实际完成后生效。

| 时长 | 稳行：重复奖励倍率 | 险行：在稳行结果上再乘 |
| --- | ---: | ---: |
| 30 分钟 | 2 倍 | 1.5 倍 |
| 60 分钟 | 3 倍 | 1.5 倍 |
| 120 分钟 | 5 倍 | 1.5 倍 |

逐种资源独立向下取整；例如野狼重复奖励修为 4、残页 1，30 分钟稳行得修为 8、残页 2，险行得修为 12、残页 3。长任务效率可低于持续手动刷图，以换取无需反复点击；奖励过高或过低先通过试玩调整配置，不增加新货币。

**R28 预览与结果。** 开始前看得到时长、结束时间、敌我快照、护行阵成本、确定性胜负预估和各资源预计所得。领取结果时写明“任务所得”和同期普通离线收益各是多少；不把天气、每日目标、镇压收益冒充历练奖励。结果可在人物修仙录回看，至少有节点、难度、时长、实际奖励和完成时间。

### 3.3 闭关倒计时

**R29 闭关规则。** 闭关占用同一任务位，无敌人和风险档、无护行阵成本。开始时锁定**当时的修为与灵气实际基础产速**，只计已生效的建筑与主修功法，不纳入 v0.4 每日一次的天气/星象奖励。到期可领取的额外闭关奖励 = 锁定产速 × 任务时长秒数 × 10%，修为与灵气分别保留到 1 位小数。例：修为 1/秒、灵气 0.25/秒时，30 分钟额外得修为 180、灵气 45；正常挂机同期所得照常独立累计。开始后升级建筑、换功法不追改该次闭关所得。

**R30 闭关状态展示。** 修炼页提供开始、剩余时间、到期领取与中止入口；其他页面页头也能看见当前长期任务摘要并返回对应页面。文案要说明“本版闭关是额外计时修行，不锁住其他即时操作”，避免误以为开了闭关就不能历练或换装。到期提示与结果面板可关闭再打开，刷新后仍能领取。

### 3.4 中止、时间异常与重复保护

**R31 中止。** 进行中的任务可中止，须二次确认并列出“本次任务奖励为零、护行阵费用不返还”。中止与清空任务位同事务提交，记录一次结果；反复点击不能多扣费。已到期任务先进入结果领取，不用中止规避或重复领取。

**R32 时间异常与并发。** 系统时间回拨时，进度不倒退到开始之前，不产生负资源，也不能用旧时间重复开始/领取。多标签页同时开始、领取或中止时只允许一个写入成功，另一个重读最新存档并给清楚的状态提示。服务重启、浏览器刷新、页面路由切换均不得丢任务。界面成功回执必须在本地存档提交成功后出现。

## 4. 存档、迁移、AI 与隐私

1. 存档 schema 从 v3 升到 v4。新增一份可为空的长期任务记录和最近一条已完成/已中止结果；与资源、修仙录、修订号一起写 IndexedDB。旧 v1/v2/v3 档导入或自动升级时默认无长期任务，不改变已有资源、镇压、每日目标、天气/星象状态；升级前保存可恢复原档，失败保留原档。
2. v4 导出文件必须包含正在进行或已到期未领取的任务，导入到新浏览器后按原绝对结束时间恢复，不从导入时间重新计时。校验任务类型、节点解锁、开始与结束时间、时长档、成本、快照和状态；畸形档拒绝且不覆盖现档。导入当前存档前沿用 v0.3 的覆盖提示与备份恢复。
3. 任务奖励与取消结果由确定性引擎提交；AI 后端仍只写原有际遇文案，不接收完整存档或长期任务数据。无网络、仅用模板或模型超时，不影响倒计时与领取。新增玩法不增加模型调用、云计时器或通知权限。
4. 长任务开始时将规则版本、敌我快照和奖励公式所需数据写入存档。若应用升级了配置，已启动任务仍按开始时的快照完成；不可在发布后悄悄改动在途任务所得。结果确认后只保留必要的事实摘要，不无限累积计时日志。

## 5. 页面与状态验收

| 场景 | 必须看到和验证的结果 |
| --- | --- |
| 未解锁与选择 | 未首镇压时说明条件；解锁后两类入口可找到；30/60/120 分钟、稳行/险行、护行阵成本与预计结果清楚可读。 |
| 开始与不足 | 同一档刚好够 30 灵石可开护行阵；不足时说明缺口，不能部分扣费；预计难胜档不可开始；成功开始后只出现一个持久任务。 |
| 开始→离开→刷新→回来→结束 | 刷新或关闭重开后任务 ID、选择、已支付费用和结束时间一致；到期由时间戳判断，玩家不必保持页面打开。 |
| 29:59 / 30:00 边界 | 30 分钟任务在 29:59 不可领取，30:00 可领取；倒计时无负数；晚回来奖励不增长。 |
| 快照锁定 | 任务期间换装、改功法或升级建筑，既有任务预估和最终奖励不回算；新的普通收益按原规则结算。 |
| 历练领取 | 只得锁定的重复奖励，不发首胜装备、不解锁节点、不触发 AI 际遇、每日战斗目标或天气/星象限次奖励；重复点击/刷新只领一次。 |
| 闭关领取 | 额外修为/灵气与开始时快照计算一致，和普通挂机收益分列；切换页面或离线后仍可领一次。 |
| 中止与占位 | 运行中确认中止后无任务奖励、护行阵费不退；未领取任务占用唯一任务位，不能再开第二项。 |
| 长时间离线 | 开始 2 小时任务，14 小时后回来：普通离线收益最多按 12 小时，长期任务只完成一次、不自动续期。 |
| 旧档与在途任务导入 | v1/v2/v3 档无损迁到 v4；v4 在途与到期档导出再导入后时间、结果和领取状态正确；坏档不覆盖现档。 |
| 时间回拨与双标签 | 无负收益、重复领奖或两项并行任务；冲突后读取最新档并给可理解提示。 |
| 360/390/430px、桌面与深浅色 | 任务预览、风险依据、倒计时、中止确认及结果在窄屏可读可点，底栏不遮挡关键按钮；减少动效不妨碍查看进度。 |

阶段交付继续按 `AGENTS.md` 提供自动化测试、真实浏览器走查、关键截图、可操作验收步骤及阶段闸门是否表。长任务至少要验证页面刷新、浏览器关闭、服务重启、存档导出导入及双标签竞争；只看到倒计时走动不算验收通过。

## 6. 试玩观察与调整

- 首轮观察玩家是否理解“同一时间只能安排一项”“到期需手动领取”“护行阵只作用本次历练”；记录玩家选择的时长/难度、中止率、到期后领取率，以及是否仍使用即时战斗。
- 若长任务让残页或闭关修为过剩，先调整倍率；若 2 小时等待让玩家失去回访意愿，先调整时长或收益，不通过强制签到与付费加速解决。
- 无匿名上报时只使用现场试玩与玩家自愿提供的本地结果，不声称有全量留存或任务完成率数据。

## 7. 待审阅决策

推荐 v0.5 只做**一个可恢复的长期任务位**，容纳持续历练和闭关；稳行/险行两档、30/60/120 分钟、一次性的护行阵为首轮基线。任务倍率与护行阵成本均可在试玩后调整。确定本版范围后再拆分开发与验收；后续随机资质、概率小进阶及更多成长内容不在 v0.5 自动启动。
