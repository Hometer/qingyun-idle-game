# 「青云修仙录」产品需求文档 v0.3

> 状态：范围已确认（A1～A9、B1～B4 + AI 开关），已进入开发。本文按[参考站体验对照与 v0.3 候选清单](../阶段文档/规划/参考站体验对照与v0.3候选清单.md)的推荐范围起草。

## 1. 版本定位

### 1.1 要解决的问题

v0.2 已能完成“领取收益 → 小进阶 → 历练与镇压 → 洞府、功法和装备成长 → 渡劫筑基”的规则闭环。v0.3 要让玩家在每一步都容易回答三个问题：**我现在该做什么、做之前会发生什么、做完实际得到了什么。**

本版以首次进入至筑基的可理解性为中心，整理五入口界面、反馈与个人记录。保持 v0.2 的数值、地图数量和核心规则。目标仍是喜欢修仙文字氛围、短时上线决策并能离线积累的单机网页玩家。

### 1.2 相对 v0.2 的增量

| 类型 | 本版内容 |
| --- | --- |
| 引导 | 一次性首玩目标卡；创建角色页增加随机道号；首次进入说明存档与 AI 文案的数据使用。 |
| 修炼 | 当前境界与两种门槛的进度、实际产速和来源、明确的可执行状态、进阶结果。 |
| 历练 | 战前节点详情、确定性胜负预估、战后结果摘要、镇压产出说明。 |
| 际遇 | 选定分支后展示真实故事结果和引擎发放的准确奖励。 |
| 背包与人物 | 换装前后属性对比；个人修仙时间线。 |
| 设置与呈现 | 统一移动端页面结构；浅深色与减少动效；存档信息与最近发起导出的时间。 |
| 图鉴与世界观 | 已解锁内容的小图鉴；洞府与地图的半文半白短文案。 |

五入口、离线结算、自动战斗、四建筑、两功法、三装备位、五波天劫、本地存档、AI 代理及模板降级沿用[v0.2 PRD](PRD-修仙放置游戏-v0.2.md)。本文未改写的 v0.2 条款继续有效；若两版出现冲突，以本文明确标注的增量为准，其余以 v0.2 为准。

### 1.3 本版不做

不增加随机灵根资质、修炼倍率、概率小进阶、持续历练、每日任务、天气或星象加成、镇压复聚、更多装备位、随机词条、复杂炼丹、师承、道侣、灵兽、寿元与轮回。不扩充炼气至筑基之外的境界，不新增付费或账号。后续建议顺序见参考站候选清单，尚未成为承诺。

## 2. 玩家主流程

1. 首次打开：看到游戏名称、存档留在本机的说明，以及 AI 际遇会发送哪些最少信息；选择使用 AI 文案或仅使用模板。输入或随机取得道号，自选五行灵根，进入游戏。随机道号只改名字，不影响属性。
2. 首玩：界面显示当前目标及直达入口。依次引导领取收益、第一次小进阶、首个节点首胜并镇压、查看一次劫势。玩家可自由去其他入口；目标完成后收起，不重复发奖。
3. 日常决策：修炼页展示当前境界、修为与灵气进度、实际产速及来源。条件不足时指出缺什么、可去哪里获取；条件满足时显示明确的主操作。
4. 历练：先看敌人属性、预计胜负、首胜或重复奖励和镇压收益，再决定是否开战。战后立即看结果摘要，可展开完整战报。遇到际遇时先选分支，再看实际故事结果与奖励。
5. 成长与回看：建筑、功法、丹药与装备操作前看当前效果、下一效果和消耗；完成后看变动结果。人物页可回看已发生的重要修行节点。
6. 存档：设置页可查看版本、最近发起导出的时间、导入与重置的影响；旧档升级后保留原进度。

## 3. 功能需求

### 3.1 页面结构与首玩引导

**R01 统一页面结构。** 页头、正文和底部五入口使用同一内容宽度；桌面端保持清楚的手机网页阅读区域，手机端适配 360px、390px、430px 等常见窄屏。底栏不遮住按钮、弹窗底部或系统安全区域。重要信息先于次要说明出现，当前入口有明显选中状态。页面滚动后页头和导航仍能使用。浅色和深色下层级一致。

**R02 首玩目标卡。** 新角色创建后显示四个一次性目标：①领取一次收益；②完成首次小进阶；③击败并镇压首个历练节点；④查看一次天劫预览。每项有当前状态、下一步说明和直达按钮。③必须首胜与镇压都完成才算完成；④在炼气圆满前标为后续目标，并指引继续成长，不能给一个点不开的“立即查看”按钮；达到圆满后才提供预览入口，只要求查看，不强迫渡劫。已满足的目标自动标记，全部完成后可折叠。已有存档按当前可验证的游戏事实判断，不倒扣进度，也不凭文字日志猜测完成状态。本版目标卡不发新资源，不构成每日任务。

**R03 道号与灵根。** 创建角色保留手动输入道号和自选五行灵根，增加“随机道号”按钮。名字来自本地预设词表，可以连续换；玩家仍可手动改。随机操作不联网、不改变灵根或初始资源。五种灵根在本版继续同强度，不出现随机资质倍率。

### 3.2 修炼与决策信息

**R04 境界进度。** 修炼页主卡展示当前境界、下一境界、修为与灵气各自的当前值、门槛和完成进度。因为小进阶同时需要两种资源，不能用一个含义不明的百分比代替。炼气圆满时展示渡劫门槛及已有的五波劫势预览；筑基一层时展示本版已达终点及已有后续内容提示。数值显示和判断都来自同一规则配置。

**R05 产速与来路。** 展示当前修为、灵气的实际每秒产速；可展开查看基础产速、建筑、主修功法等确实生效的来源和合成方式。当前没有贡献的项目不伪装成加成。玩家切换功法或升级建筑后，显示值立即与下一次结算规则一致。人物页攻、防、气血可看到装备及基础值的贡献。

**R06 操作前信息。** 小进阶、渡劫、建筑升级、功法升级与切换、装备穿戴、炼丹、预置丹药、战斗及镇压，都要在点击前说明条件、成本和预期效果。条件不足时按钮不可执行，同时用文字指出缺口或解锁条件；不能只降低透明度。条件刚好满足时可以执行。由于时间收益会变化，实际执行仍以同一次状态结算后的规则校验为准；预览过时要刷新提示，不发生部分扣费。小进阶固定成功、渡劫按既有五波规则计算，不加入隐藏随机数。

**R07 操作后回执。** 完成进阶、升级、换装、炼丹、镇压和渡劫后，立即展示本次实际消耗、得到的效果与下一步。失败要说明原因与恢复路径。回执内容来自已提交的状态变更，不能仅根据按钮文案推测；重复点击或刷新不能重复领奖、扣费或晋级。重要结果在相关页面可回看，短暂顶部提示只作辅助。

### 3.3 历练、战斗与际遇

**R08 节点详情。** 保留两张地图、每图三个节点和即时自动战斗。已解锁节点在开战前可查看敌人攻、防、气血、境界要求、本次属于首胜或重复战斗、对应固定奖励，以及该节点被镇压时的每小时产出。未解锁节点写清前置条件。现有规则可确定胜负时，给出基于当前装备与功法的“预计可胜/预计难胜”，并说明预测依据；状态变化后重新计算。预测不能暗示不存在的随机胜率。镇压中需显式显示当前目标与产速，切换目标前说明未来产出变化。

**R09 战斗结果。** 战斗后先展示胜负、实际奖励、是否首次通关、是否解锁后续节点，以及战败时最主要的属性短板。完整逐回合战报可展开查看，并保留已确认的引擎战斗结果。战斗失败不伪称获得奖励；用户离开结果面板后仍可在本次页面状态中重新查看最近战报。

**R10 际遇结果。** AI 或模板文案仍只描述预设事件，不决定选项和奖励。玩家选择后先提交引擎结果，再显示结果面板：事件标题、选择、分支结果文案、准确的资源变化和“继续修行”。奖励以配置和已提交的状态为准；AI 文案若不可用，使用对应模板，不阻断选择。未确认的选项在刷新后仍可恢复，已确认的选项不能重复领取。结果文案不得暗示与实际奖励冲突的好处。

### 3.4 背包、人物与个人修仙录

**R11 装备比较。** 背包保留武器、护甲、佩饰三个槽位及现有固定装备。查看候选装备时显示当前装备与候选装备的属性、穿上后的攻/防/气血差值。已穿戴项明确写“穿戴中”，不可重复执行穿戴；没有候选时说明获取路径。护劫丹的持有、预置状态、炼制成本及可用条件清楚可见。

**R12 个人修仙录。** 人物页增加轻量时间线入口，按时间记录已发生的创建角色、首次小进阶、地图首通、镇压、重要际遇和渡劫结果。每条至少显示事件名称、发生时间和可核对的结果；有实际奖励时显示奖励。只使用本地引擎确认过的事实，不由 AI 编造经历；不生成长篇传记、称号或社交关系。普通重复战斗可只保留最近记录，首次通关与渡劫等里程碑应长期保留。旧档无法可靠还原的历史显示“此前记录未收录”，从升级后继续记，不虚构过去。

### 3.5 隐私、存档与设置

**R13 首次数据说明。** 角色创建前用简短文字说明：游戏进度保存在当前浏览器本地，清理浏览器数据或换设备可能失去进度，应定期导出；AI 际遇会把事件类型、道号或替代称呼、灵根、境界、地图、最近两条修行摘要及预设选项含义发送给国内模型服务，完整存档不会发送。玩家可选择 AI 文案或仅用模板，后者不触发模型请求；设置中可再次调整。升级而来的旧档若没有记录这一选择，首次进入 v0.3 时也展示一次说明，不影响已有进度。说明不能误写“游戏完全不联网”。密钥和访问码不展示在说明、导出文件或诊断信息中。

**R14 存档设置。** 设置页展示存档版本及“最近发起导出时间”；浏览器无法保证文件最终保存，因此不能把发起时间称为“备份成功”。导入前展示会替换当前进度，成功导入后原档有可恢复备份，设置页提供“恢复导入前存档”入口并在恢复前确认；失败不覆盖现档。重置需明确二次确认并建议先导出，文案称“新开一局”，不称“轮回”。保留 v0.2 的坏档校验、多标签页保护、离线结算与待结算渡劫恢复要求。

**R15 显示偏好。** 设置页提供浅色、深色、跟随系统三档主题，以及减少动效开关。偏好保存在浏览器本地，刷新后保持；减少动效时不使用会妨碍阅读和操作的长动画。现有即时战报无需设置播放速度；若本版实现逐回合播放，必须有跳过或速度控制。主题和动效不影响游戏数值或离线结算。

### 3.6 图鉴与世界观

**R16 小图鉴。** 人物页或独立入口提供已解锁内容的图鉴：已见过的地图、敌人、装备、功法、建筑及其获得或解锁来源。只收录当前已实现且玩家已解锁的内容；未解锁项显示为“尚未遇见”占位，不剧透数值。图鉴只读，不发放奖励、不影响规则。

**R17 世界观短文案。** 洞府与两张地图各配少量准确、易读的半文半白环境文案，用于增强氛围。引典须核实出处，不得杜撰；文案只作展示，不改变任何规则、数值或判定。

## 4. 数据、AI 与兼容要求

1. 玩家进度、首玩目标状态、修仙录和显示偏好均留在浏览器本地；后端继续只代理 AI 文案请求，不保存玩家存档。AI 关闭、超时或校验失败时使用模板，战斗、收益和际遇奖励照常结算。
2. v0.2 存档必须能升级到 v0.3，姓名、灵根、资源、境界、建筑、功法、装备、地图、镇压、际遇、渡劫结果及时间戳均不丢失。升级前保存可恢复的原档；迁移失败保留原档并给出可理解的提示。v0.2 导出文件在 v0.3 中应可导入并迁移。
3. 个人修仙录的里程碑必须和获得进度的操作一起持久化，刷新或进程重启后仍可查看；相同事件不会重复写入。普通记录的保留上限可配置，里程碑不随普通记录截断而消失。
4. 操作回执中的资源变化、战斗预估和产速明细由游戏规则得出。AI 不参与规则、胜负、概率、奖励、存档迁移或计时判断。新增页面不增加模型调用次数和费用来源。
5. 导出文件不含模型密钥、访问码及其他凭证。日志和诊断不记录完整存档、姓名以外的无关个人数据或完整 AI 输入输出；错误提示不泄露堆栈。

## 5. 页面与状态验收

| 场景 | 必须看到的结果 |
| --- | --- |
| 新角色第一次打开 | 数据说明准确；可选 AI 或模板；随机道号可反复换且不影响灵根与初始数值；进入后出现首玩目标。 |
| 旧 v0.2 存档打开 | 原进度、装备、资源、镇压与待结算事件均保留；无法还原的修仙录历史不会被编造。 |
| 修为足、灵气不足 | 修炼页分别显示两种资源进度；进阶按钮不可执行，明确显示缺少多少灵气；待收益领取后可重新判断。 |
| 产速变化 | 升级修炼室或切换功法后，产速及来源同步变化；已结算收益不被新倍率重算。 |
| 战前决策 | 看得到敌我能力、首胜或重复奖励、镇压产速和确定性胜负预估；装备变化后预估同步更新。 |
| 战斗或际遇完成 | 显示引擎实际结算的奖励；战败无胜利奖励；际遇刷新后不能重复领取。 |
| 换装与丹药 | 候选装备显示穿上前后攻/防/气血差值；已穿戴项不可重复操作；材料不足时显示缺口。 |
| 渡劫 | v0.2 的五波预览、失败恢复与重复点击保护仍有效；结果回执写明实际消耗和下一步。 |
| 本地存档 | v0.2 导出可迁入；坏档不覆盖现档；显示的是发起导出时间，不宣称浏览器已成功保存文件。 |
| AI 不可用 | 模板事件仍可读、可选、可显示准确奖励；选择仅用模板后不请求模型。 |
| 窄屏及桌面 | 360px、390px、430px 手机宽度及桌面浏览器均可完成创建角色到筑基；底栏不遮挡主操作与弹窗。浅深色、减少动效均可用。 |

以上场景同时检查键盘可操作性、文字可读性、加载与失败状态，以及刷新后的状态恢复。界面显示必须与引擎结果一致；不能用静态示意数据冒充真实结果。

## 6. 效果观察与发布边界

- 首轮找 5～10 位目标玩家按真实流程试玩，记录他们是否能独立找到下一步、说清战前收益与风险、解释渡劫失败原因，以及首次筑基耗时。阈值以试玩结果再定，不为达成时长目标故意增加等待。
- 观察首玩四步中卡在哪一步、战斗前查看详情的使用情况、结果面板是否帮助玩家说清奖励。无匿名上报时，只能用现场试玩和本机记录，不声称已有全量留存数据。
- v0.3 是现有项目的需求迭代，不自动意味着阶段 3 已验收或项目已上线。开发前需先确认本稿范围；开发后按 `AGENTS.md` 的阶段闸门、真实浏览器走查及证据包验收。

## 7. 待确认决策

本稿按产品经理确认纳入 A1～A9、B1～B4，并确认 AI 文案开关（可选“仅用模板”）要做。后续版本功能未纳入本稿。
