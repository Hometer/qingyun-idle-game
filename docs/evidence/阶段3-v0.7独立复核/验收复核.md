# v0.7 独立复核与修复清单

日期：2026-09-25。结论：**暂不通过 v0.7 复核，暂不启动 v0.8 PRD**。本轮只检查、记录问题，没有修改业务代码。真实玩家试玩与物理真机操作仍按已定计划留到总体验收。

## 已核对的结果

- 对照 `docs/PRD/PRD-修仙放置游戏-v0.7.md` 检查筑基进阶、云岭古道、结丹试炼、存档导入与现有证据包。
- 前端自动测试 **82/82**、后端自动测试 **14/14**、`npm run typecheck` 通过。既有 v0.7 证据包记录生产构建通过，本轮没有重复构建。
- 用独立的 v6 存档调用实际 `importSave` / `previewJindanTrial`，并在隔离浏览器中复现资源不足时的修炼页。截图：[资源不足时的结丹试炼页](01-资源不足无结丹预览.png)。

## 给 DeepSeek 的修复项（按优先级）

### P0-1：v6 地图缺字段会丢进度或触发导入异常

**复现**：从正常 v6 导出档中删去 `maps.map_qingyun`，保留原档三个青云节点均已首通的其他字段，再调用导入。实际返回 `ok: true`，导入后青云三个首通状态变成默认的未通关状态。若只删去 `maps.map_yunling.node_golem`，导入也返回成功，结果里该节点仍缺失；若删去 `node_ape`，导入在 `syncYunlingUnlock` 抛出异常，未返回可理解的错误。

**预期**：v6 档缺任一地图或必需节点时拒绝导入，原档不被覆盖。旧版本可按各版本的真实存档结构迁移后来新增的地图，但不得把本应存在的旧地图静默重置。导入路径即使遇到异常，也应给出失败提示并保留当前进度。

**定位**：`frontend/src/engine/engine.ts:1295` 的 `validateMaps` 对缺失地图和节点直接放行；`normalizeSave` 在 `:1548` 用默认地图浅合并；`syncYunlingUnlock` 在 `:810` 假定首节点必然存在。对应 PRD 第 5 节的“无效地图节点拒绝导入、失败不覆盖现档”。

**修复验收**：覆盖 v6 缺整张旧地图、缺新地图、缺首/中/末节点；旧 v1～v5 缺新地图仍能无损迁移。每个坏档均返回 `ok: false`，不抛异常、不替换现档。

### P0-2：畸形结丹战报被导入，修炼页存在渲染风险

**复现**：在正常 v6 档中设置 `jindanTrial` 为具有合法数字/布尔字段、`waves` 只有一波、`log: [{"bad":"object not string"}]` 的对象。实际 `importSave` 返回 `ok: true`，并原样保留对象日志。修炼页直接把日志项作为 React 文本节点渲染；对象日志会触发子元素类型错误。此处页面崩溃是基于渲染代码的推断，导入放行已由引擎复现。

**预期**：v6 结丹记录必须具备五波结构，日志每项是字符串，并验证波次与胜负等必要字段；坏记录拒绝导入且不影响当前存档。已有合法旧档保持兼容。

**定位**：`frontend/src/engine/engine.ts:1480` 仅检查 `waves` / `log` 是数组，未检查五波数量或日志元素类型；`frontend/src/app/xiulian/page.tsx:279` 直接渲染日志项。

**修复验收**：缺波、超额波、对象日志、空记录等坏 v6 档均拒绝；合法结丹战报导出再导入后完整显示。

### P1-1：资源不足时无法预览结丹试炼，也没有明确差额

**复现**：筑基圆满且已首通护丹灵，修为和灵气均足额，灵石为 2999（只差 1）。`previewJindanTrial` 返回空波次、零成本；修炼页只显示“需修为 12000、灵气 1600、灵石 3000”，不显示五波、减伤来源、丹药效果、预计胜负或“还差 1 灵石”。见上方截图。

**预期**：已满足境界和首通条件时，即使资源不足，也能查看五波和固定成本，并看到各项当前数量及差额；只有挑战按钮不可提交。仍按实际执行时的最新资源二次校验。

**定位**：`frontend/src/engine/engine.ts:1125` 将资源校验和预览合为一道闸门，`:1142` 提前返回空预览；`frontend/src/app/xiulian/page.tsx:222` 只在 `ok` 时显示完整预览。对应 PRD R39 的预览及“说明缺口”要求。

**修复验收**：以灵石差 1、修为差 1、灵气差 1、未首通第三节点四种状态分别验证展示与按钮；资源补齐后无需重新准备即可看到同一战斗预览。

### P1-2：预计失败的确认框没有提示仍会扣费

**复现**：令五波预览显示“预计失败”，点击“开始结丹试炼”。现有确认文案仅为“确定结丹试炼？消耗……，失败境界不退”，没有明确提醒“本次预计失败，仍会消耗资源和预置丹药”。

**预期**：预计失败时，二次确认框明确显示预计失败及仍会扣除的修为、灵气、灵石和已预置丹药；取消不扣费。预计成功时也保留确认和成本展示。

**定位**：`frontend/src/lib/game-context.tsx:584`。对应 PRD R39 的预计失败提示与人工确认要求。

**修复验收**：预计失败时分别点击取消、确认；核对资源和丹药只在确认且持久化成功后扣一次。

### P2：v0.7 PRD 状态仍写“待审阅、尚未启动开发”

`docs/PRD/PRD-修仙放置游戏-v0.7.md` 的标题、导语和结尾仍为起草时状态，与已开发及当前复核状态矛盾。修复后同步改为已确认/已开发/待复核结论，不改动已确认的需求规则。
