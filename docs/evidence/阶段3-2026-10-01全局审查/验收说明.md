## 自己打开和体验

本次生产构建预览在 **http://localhost:5183**；原项目默认启动地址为 http://localhost:5173。不同端口的存档隔离。审查结束时 5183 服务保持运行；关闭终端或重启电脑后，按 README 的启动方法恢复服务。

1. 浏览器打开 5183。如果当前浏览器没有存档，会看到命盘页。点“自行设定”，核对是否能选择双灵根或风灵根，目前应看不到这些选择。
2. 填一个道号，选“仅用模板”，点“踏入仙途”。顶部点“领取收益”，底部或左侧点“历练”，在野狼行点“战斗”，胜利后点“继续修行”。若出现际遇，选一个选项并继续，再点野狼的“镇压”。
3. 在历练页往下找到“山河委托”，核对当天是否同时提供战斗和制作两项。目前首次主线胜利当天仍只有制作候选。
4. 回到野狼，选“挑战 · 奖励提升”，点“详情”，会看到常法/破势/守拙。选择守拙再点“开战”，最近一战应记录守拙。直接点列表的“战斗”会立刻按常法结算。
5. 后期炼器和坏档问题看本目录截图；技术复现脚本已由本轮运行，不需要你手动修改存档来核对。

当前问题会使一些存档无法导入；本轮不把正常开局可玩当作全部功能验收完成。

## 真实模型核对

本轮使用现有后端本地配置，以虚构“审查修士”及最少事件信息调用一次古井后续 `event_well_down`，返回 `source=model`，结构审核通过，包含两项与请求对应的选项。返回正文如下，供产品经理看文案效果：

> 青云山阴，古井苔深。你已探得井底残文，字如金丝，隐有清鸣。今携拓本复至井畔，寒气扑面，井壁水痕似映出旧日符箓。审查修士以金灵根微感，残文与井底暗合，如锁待钥。再探则须循线而下，封存则恐失其真。井中回声，似问君心。

这一条是真实模型结果；费用失败场景使用假响应，单独标在报告中。尚未覆盖连续际遇所有分支的真实模型效果。
