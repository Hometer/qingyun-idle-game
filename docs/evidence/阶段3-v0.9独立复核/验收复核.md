# v0.9 独立复核：未通过

日期：2026-09-25。对照已确认的 `docs/PRD/PRD-修仙放置游戏-v0.9.md` 及现有 v0.9 证据包。本轮只做独立复核，不改游戏实现。**先修复复验，再起草 v1.0 PRD。**

## 可直接发给 DeepSeek 的修复清单

### P0-1：v8 坏档可清除当日挑战标记，重复领取同一秘境奖励

- **独立复现**：用金丹角色当天挑战灵药谷获胜，实得灵草 30。复制导出 JSON，保持 `schemaVersion: 8`，只删除 `secretRealmUsed`，然后导入。实际 `importSave` 返回 `ok: true`，再次挑战同一秘境也返回成功，灵草变为 60、探索记录变成两条。将 `secretRealmDate` 改成 `invalid-date` 也会被接受，进入时自动重置次数并再次发奖。把胜利记录的灵草奖励从 30 改成 999999，导入仍返回成功。
- **定位**：`frontend/src/engine/engine.ts:1491-1511` 对缺失的当日状态直接放行、不校验日期格式和奖励是否符合秘境配置；`:1799-1801` 把缺失的 v8 状态补成“未探索”。`:188-193` 遇到非法日期会重置全部次数。现有测试只覆盖“状态值不是布尔”，没有覆盖 v8 字段缺失、非法日期、奖励被改及重复领取。
- **修复验收**：v1～v7 合法档可按其版本补新字段；v8 缺日期/任一秘境次数/记录、日期格式非法、记录奖励与胜败或配置不符、同日次数与记录矛盾时拒绝导入且保留当前存档。正常同日只可挑战一次，刷新、导入与双标签后均不可重复领奖。补真实 v8 坏档回归测试，不要用当前版本档冒充旧版样例。

### P1-1：跨日后页面仍显示昨天的“已探索”，预估也可能与当日实战不同

- **复现依据**：引擎的 `settle` 会按日期重置次数，但历练页 `frontend/src/app/lilian/page.tsx:135-153` 读取原始 `state.secretRealmUsed`，不读每秒更新的 `view`。页面保持打开跨过午夜后，已挑战秘境的按钮仍被禁用，直到刷新或其他操作更新存档。预估也读取旧 `state.daily.astrology`，而真正进入时先 `settle` 刷新星象，跨日战斗可能与显示的“预计可胜/难胜”不同。
- **修复验收**：保持页面打开跨日，三个按钮和剩余次数自动切到新的一天；战前预估与实际执行使用同一当日状态，星象变化不会使胜负预估失准。覆盖跨日且前一天已挑战、跨日星象变化两种场景。

### P1-2：AI 进入叙事可重复调用，也可尚未生成就开始探索

- **复现依据**：`frontend/src/lib/game-context.tsx:539-569` 每次点“进入秘境”都调用 `generateEncounter`，叙事和待进入秘境只存在 React 内存；取消后再点、刷新后再点都会重新请求。`frontend/src/app/lilian/page.tsx:263-274` 在请求未完成时就显示默认正文且“开始探索”可点，玩家可在真实 AI/模板叙事到达前直接结算。与 PRD R47 的“展示一次、刷新不重复调用、可恢复”不符。
- **修复验收**：进入叙事有明确加载/失败降级状态，叙事就绪前不能误触发探索；同一次当日进入流程在取消、刷新、重试时复用已保存的叙事/状态，不重复产生模型费用；战斗与奖励仍由引擎决定。

### P1-3：图鉴没有秘境“首次探索/首次成功”记录

- **复现依据**：引擎写入 `secretRealmLog` 与修仙录，但人物页图鉴 `frontend/src/app/renwu/page.tsx:181-232` 只显示地图敌人、装备、功法、建筑；全仓库没有读取 `secretRealmLog` 来生成图鉴内容。与 PRD R48、验收场景“记录与回看”不符。
- **修复验收**：每个秘境分别显示首次探索与首次成功（尚未发生则不伪造），可在人物页回看；失败后次日首次成功、刷新、导出导入和旧档迁移均正确。

### P1-4：秘境结果面板把普通挂机收益混成秘境奖励

- **复现依据**：`enterSecretRealm` 先 `settle(state, nowMs)` 结算挂机收益。`frontend/src/lib/game-context.tsx:571-587` 随后用操作前的原始 `state` 与操作后状态做资源差值展示。若等待数秒再进入，失败时虽然秘境奖励为 0，结果面板仍可能显示挂机所得修为/灵气；胜利时也会把普通收益加进秘境回执。
- **修复验收**：结果面板只列本次秘境 `SecretRealmLog.reward`；失败明确显示“无秘境奖励”。普通挂机收益如需显示，应单独标名，不混入秘境所得。

### P2-1：秘境卡缺少战前我方属性和明确的今日剩余次数

- **复现**：现有[秘境区块截图](../阶段3-v0.9/01-秘境区块.png)只列敌方攻防气血、奖励与“预计可胜”；未列我方攻防气血，也未显示 1/1 或 0/1 的今日剩余次数。与 PRD 第 2、4 节要求的战前信息不齐。
- **修复验收**：三张卡均显示敌我属性、胜负预估、境界门槛和今日剩余次数；360px 宽度下仍可读可点。
