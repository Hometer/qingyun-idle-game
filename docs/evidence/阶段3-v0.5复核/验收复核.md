## 阻塞问题

| 优先级 | 问题与影响 | 证据 | 建议调整 |
| --- | --- | --- | --- |
| P0 | 双标签页可能覆盖较新的存档。`persistSave` 只检查待写修订号是否大于当前值；旧标签页做一次 `settle` 再操作就可能产生更高修订号，写入后覆盖另一页已开始或已领取的任务。 | `frontend/src/engine/storage.ts:29-42`；`frontend/src/engine/engine.ts:541-543` 的结算会递增修订号。 | 每次操作携带读取时的基准修订号，在 IndexedDB 同一读写事务中要求当前修订号与基准值相等；冲突后重读，再决定是否重试。补双标签页开始/领取/中止的浏览器复验。 |
| P0 | v4 坏档可通过导入并在到期领取时抛错。`validateLongTask` 只看类型和两个时间，缺少 `snapshot` 的任务仍导入成功；`claimLongTask` 直接读取 `snapshot.expectedReward`。玩家可能无法领取已到期任务。 | `frontend/src/engine/engine.ts:1129-1135`、`:339-345`；临时 Vitest 定向复现通过。 | 校验任务 ID、时长、时间关系、节点、解锁、难度、成本、规则版本、快照各数值和奖励资源；校验已完成结果。导入失败时保留现档，增加坏档测试。 |
| P0 | 到期任务仍显示“中止”，且引擎允许中止；玩家已等完时间后点击中止会得到零奖励并清空任务。 | `frontend/src/components/Shell.tsx:37-40`、`frontend/src/engine/engine.ts:357-368`；临时 Vitest 定向复现通过。 | 到期只显示领取；引擎对 `now >= endAt` 的中止请求明确拒绝，补时间边界测试。 |
| P1 | 未首镇压也能开启闭关，历练入口未解锁时也没有说明条件。与 PRD 第 2.1 节、第 5 节不符。 | `frontend/src/engine/engine.ts:251-257`、`:292-302`，`frontend/src/app/xiulian/page.tsx:87-109`；临时 Vitest 定向复现通过。 | 在引擎开始和预估处统一检查 `canArrange`；页面显示“首次镇压后解锁”。 |
| P1 | 领取回执只显示任务奖励加上一句普通收益已结算，未列出同期普通离线收益具体数额；人物“修仙录”只有“领取结果”摘要，无法回看节点、难度、时长和实际奖励。 | `frontend/src/lib/game-context.tsx:304-316`；`frontend/src/app/renwu/page.tsx:147-157`。 | 领取时分别计算任务所得和普通收益；人物页展示 `lastLongTaskResult` 的必要事实摘要。 |
